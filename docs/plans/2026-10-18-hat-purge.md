# Delete and purge (plan 9c): the per-hat purge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ] `) syntax for tracking.

**Goal:** The operator can purge a hat (umbrella §6.10, kernel §5.5).
- **The routes:** `POST /api/hats/{id}/purge` needs a fresh step-up. `GET /api/hats/{id}/purge` previews what would go.
- **Freeze first:** the purge records the hat in `purged_hats` and deletes its path rules. From then on no session, rule, default or re-assignment can enter the hat or leave it.
- **What it deletes:**
  - every session of the hat, each in its own transaction and as plan 9a deletes one;
  - its project recents and push policies, which go with the hat row.
- **Delete last:** the hat row goes after everything else.
- **Resumable:** after a crash or a refusal, a re-POST finishes it.
- **The host:** after every reconciled handshake it gets `forget_hat` for each purged hat, so it can delete that hat's composed agent home (plan 8).
- **The gateway:** its own purge hook runs first (plan 8, A15).

**Architecture:**
- **Kernel** (`hennery-kernel`):
  - the migration that adds `purged_hats(hat_id PK, owner_id, purged_at)`, kernel migration 10;
  - `Hosts::begin_purge`, which freezes the hat: it re-checks that the hat is no default, inserts the row and deletes the rules;
  - `Hosts::finish_purge`, which deletes the hat row;
  - `purged_hats` and `is_frozen`;
  - `hat_exists` and `update_hat` refuse a frozen hat;
  - `HatRecord.purging`;
  - `LifecycleHooks::on_hat_purged`.
- **Sessions store:**
  - `create_session`, `request_resume` and `reassign_hat` (source and target) refuse a frozen hat inside their own transactions;
  - `hat_sessions`, `unassigned`, `purge_counts`;
  - `delete_session_owing_checkpoint`.
- **Routes** (`hennery-sessions/src/hats.rs`):
  - the preview (`PurgePreview`) and the purge (`PurgeResult`), with step-up on the POST alone;
  - `delete_as_read`, which shares 9a's `close_deleted_on_host`;
  - one checkpoint per purge.
- **Wire:** `HatItem.purging`, `PurgePreview`, `PurgeResult`, and `CollectorFrame::ForgetHat`. The host's arm only logs; plan 8 deletes the home.
- **ws.rs:** sends `forget_hat` for every `purged_hats` row after `ws::ready`.

**Tech Stack:** Rust (edition 2024, MSRV 1.88), rusqlite 0.40, tokio, axum 0.8. No new crates.

**Spec:**
- umbrella §6.10: "Purge a hat removes all of its sessions, its gateway connections with their grants, and its path rules; hosts delete their composed agent homes for that hat on their next connection".
- kernel §5.5: "every session of the hat is deleted as in ACP core §4.10; … its path rules, project recents and the hat row are deleted, and the hat is recorded in `purged_hats`; … after every handshake the collector sends `forget_hat{hat_id}` for each hat in `purged_hats`".

It builds on plan [9a](2026-10-15-session-delete.md) (`delete_session`, its compare-and-set, `close_deleted_on_host`, `Checkpoints`) and on the hats plans 5a–5d. It takes up their hand-ons:
- refuse the `default_hat_id` setting and any host's default;
- delete rules before the hat;
- sessions re-assigned into a hat are that hat's;
- sessions with no hat (`hat_id = ''`) are listed for the operator.

## Decisions this plan makes where the spec is silent

Plan 9's security review confirmed these on the maintainer's behalf. A-numbers are its amendments.

1. **Freeze first, delete last, and resume on a re-POST** (decision 10).
   - The route refuses before freezing:
     - 404 for an unknown hat;
     - 409 `hat_is_default` for the `default_hat_id` setting or any host's default, revoked hosts included;
     - 409 `sessions_running` for a session `starting` or `active` on a reachable host, and then the hat is **not** frozen.
   - The freeze transaction (`begin_purge`) checks the defaults again (A2), records `purged_hats` and deletes the rules.
   - Then the gateway hook (plan 8, A15) runs, then each session's delete, then `finish_purge`, which deletes the hat row. Its recents and push policies cascade.
   - Answer: 200 `PurgeResult {sessions, rules, unconfirmed}`.
   - If anything fails partway, the hat stays frozen, and a re-POST resumes.
2. **Unreachable sessions are closed and deleted, not refused** (decision 10b).
   - Presumed-parked sessions, sessions `active` on an offline or revoked host, and sessions `starting` on an offline host are all closed collector-side, through 9a's compare-and-set, and deleted.
   - Their host closes the adapter when it returns.
   - Those sessions are listed in `unconfirmed` (A13).
3. **A frozen hat admits nothing** (A2, A3).
   - In the store, inside each transaction: `create_session`, `request_resume`, and `reassign_hat` as source or target.
   - In the kernel: `hat_exists` (rules, host defaults) and `update_hat(default_for_new_hosts)`.
   - The API answers 409 `hat_purging`.
4. **`purged_hats` is kept for good** (A7).
   - `forget_hat` goes to every host after each reconciled handshake, so a host away for any length of time still forgets.
   - Older hosts ignore an unknown frame.
5. **The preview** (decision 11) reads only, with no step-up. It returns:
   - the counts of sessions, rules and recents, without tombstones;
   - the ids of running sessions;
   - the sessions with no hat, at most 100 items, plus a count.
6. **`purging`** on the hat list item (A12), so the frontend can offer "resume purge".
7. **One checkpoint per purge.** The debt is recorded durably before the first delete. One checkpoint runs after the last delete, on every exit path.

  const NOW: i64 = 4_000_000_000;

  fn enrollment(seed: u8) -> Enrollment {
      Enrollment {
          public_key: hex::encode(SigningKey::from_bytes(&[seed; 32]).verifying_key().as_bytes()),
          name: "laptop".into(),
          host_version: "0.0.0".into(),

          HatChange::Done(hat) => hat.id,
          other => panic!("expected a hat, got {other:?}"),

  fn the_default_hats_and_an_unknown_hat_are_not_purged() {

      let personal = hosts.default_hat_for_new_hosts().unwrap();

      /// whatever else comes in between (acks, closes, answers).
      async fn forgotten(&mut self, within: Duration) -> Vec<String> {
          let mut hats = loop {
              if let CollectorFrame::ForgetHat { hat_id } = self.next().await {
                  break vec![hat_id];
              }
          };
          let _ = tokio::time::timeout(within, async {
              loop {
                  if let CollectorFrame::ForgetHat { hat_id } = self.next().await {
                      hats.push(hat_id);
                  }
              }
          })
          .await;
          hats
      }

      /// symlinks would (plan 5c), until `request` is answered.
      async fn serve_while(&mut self, request: tokio::task::JoinHandle<reqwest::Response>) -> reqwest::Response {
          tokio::pin!(request);
          loop {
              tokio::select! {
                  done = &mut request => return done.unwrap(),
                  frame = self.next() => {
                      if let CollectorFrame::ResolvePath { request_id, path } = frame {

                              request_id,
                              canonical: path,
                              exists: true,
                              is_dir: true,
                          })

              }
          }
      }

  impl std::fmt::Display for SessionsRunning {
      fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {

  /// Whether `session` may have an adapter the collector reaches (plan 9c
  /// decision 10b): `starting` or `active` on a host connected and
  /// reconciled. One presumed parked, or starting or active on a host away
  /// or revoked, is closed collector-side instead, as a delete closes it
  /// (plan 9a decision 5).
  fn running(state: &AppState, session: &HatSession) -> bool {
      matches!(session.lifecycle.as_str(), "starting" | "active") && state.hub.is_ready(&session.host_id)
  }

  fn running_ids(state: &AppState, sessions: &[HatSession]) -> Vec<String> {
      sessions
          .iter()
          .filter(|session| running(state, session))
          .map(|session| session.id.clone())
          .collect()

  /// Delete every kept session of `hat_id`, frozen for its purge (plan 9c
  /// decision 10d): each as a delete does (plan 9a decision 5), in a
  /// transaction of its own, so the store's lock is not held across hundreds;
  /// its `session_deleted` goes to its streams, which end on it (A10). One not
  /// closed is closed collector-side first, only while it is still what was
  /// read here (A4). Any that may be running, or that changed since, stops it
  /// with `SessionsRunning`: what was deleted stays deleted, and running it
  /// again goes on from there.
  pub fn purge_sessions(state: &AppState, hat_id: &str) -> anyhow::Result<PurgedSessions> {
      let sessions = state.store.hat_sessions(hat_id)?;
      let found = running_ids(state, &sessions);
      if !found.is_empty() {
          return Err(SessionsRunning(found).into());
      }
      let mut purged = PurgedSessions::default();
      for session in sessions {
          // Its host may have come back since the read above, with hundreds
          // of deletes in between: asked again, just before its own. Defence
          // in depth: a host that returns between this and the delete still
          // finds it closed only at its next handshake (decision 4).
          if running(state, &session) {
              return Err(SessionsRunning(vec![session.id]).into());
          }
          let unattached = (session.lifecycle != "closed").then(|| Unattached {
              lifecycle: session.lifecycle.clone(),
              presumed_parked: session.presumed_parked,
          });
          match state.store.delete_session(&session.id, unattached.as_ref())? {
              Deletion::Done { event, unconfirmed } => {
                  state.hub.publish(event);
                  purged.deleted += 1;
                  if unconfirmed {
                      purged.unconfirmed.push(session.id);
                  }
              }
              // A resume, or its host back with it, since it was read.
              Deletion::Refused(_) => return Err(SessionsRunning(vec![session.id]).into()),
              // Deleted meanwhile, by a delete of its own.
              Deletion::NotFound => {}
          }
      }
      Ok(purged)
  }

          Ok(sessions) => running_ids(&state, &sessions),

          sessions: purged.deleted,

          unconfirmed: purged.unconfirmed,
      })
      .into_response()
  }
