# `owner_id` everywhere (plan 3b-iii) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ] `) syntax for tracking.

**Goal:** Every row carries `owner_id` and every query filters by it (kernel spec §1, umbrella §7.4):
- The owner exists from the first start, before setup, so the pairing code and host `hennery up` writes then have an owner to carry. Setup sets that owner up; it no longer creates it.
- `hosts`, `pairing_codes` and the sessions store's six tables get `owner_id`, filled in for the rows already there.
- Every query of the operator, the host registry and the sessions store names the owner, the operator's own included (3b-i's A5, 3b-ii's A10).
- A test reads every SQL statement of those three files and fails on one that does not name the owner.
- Along the way:
  - a migration reads its version inside its transaction;
  - a password reset fails, changing nothing, unless it replaced exactly one password (3b-ii's O9).

**Architecture:**
- **Kernel** (`hennery-kernel`):
  - `db.rs`:
    - `migrate` and `migrate_component` read the version inside each step's transaction;
    - `kernel_owner(conn)` runs the kernel's migrations and returns the database's owner, the oldest row of `owners`.
  - `schema.rs`:
    - migration 3 adds `owners.set_up_at` and creates the owner if there is none;
    - migration 4 rebuilds `hosts` and `pairing_codes` with `owner_id NOT NULL REFERENCES owners(id)`, filled with that owner.
  - `operator.rs`: the operator binds to the owner when it opens.
    - `owner_id()` is that owner, set up or not;
    - `is_set_up()` reads `set_up_at`;
    - `set_up` marks the owner set up;
    - every query names the owner.
  - `hosts.rs`: the registry binds to the owner the same way, and every query names it.
- **Collector** (`hennery-sessions`): `Store::init` runs the kernel's migrations first, then its own. Migration 7 adds `owner_id` to `sessions`, `turns`, `events`, `session_catalog`, `pending` and `answer_queue`, filled with the owner. The store binds to that owner, and every statement names it. A write for a session that is not the owner's fails and writes nothing.
- **Tests** (`hennery-testkit`): `tests/owner_filter.rs` prepares every SQL statement of `operator.rs`, `hosts.rs` and `store.rs` under rusqlite's authorizer. Every table a statement touches must have its owner column read.

**Tech Stack:** Rust (edition 2024, MSRV 1.88), rusqlite 0.40 (bundled SQLite 3.53.2), tokio. No new crate, nothing new in `flake.nix`. The testkit's dev-dependency on rusqlite turns on its `hooks` feature (the authorizer). `Cargo.lock` does not change. The shipped binary (`cargo build -p hennery`, which the second clippy run checks) does not get the feature (`cargo tree -p hennery -e features -i rusqlite`); a workspace test build does, through feature unification.

**Spec:** [`docs/specs/2026-09-26-kernel-design.md`](../specs/2026-09-26-kernel-design.md) and the umbrella [`docs/specs/2026-09-25-hennery-architecture-design.md`](../specs/2026-09-25-hennery-architecture-design.md), these sections:

## Decisions this plan makes where the spec is silent

These were confirmed by a stronger-model security review on the maintainer's behalf (2026-10-01, "approve after amendments"). Each gives the choice, the alternatives, and the cost if it is wrong, so a reviewer can confirm it on its own. Decisions the review changed are marked "(amended after the security review of 2026-10-01)". Items marked **(amendment)** depart from explicit spec text and should be written back into it.

**What the review changed:**
- A1: the audit requires an owner column compared with a parameter, so a join that compares owner columns only with each other fails (decision 6).
- A2: the audit catches an `INSERT … SELECT` from its own target (decision 6).
- A3: the audit fails on SQL in a file it does not list; `EXEMPT` names the two that hold SQL on purpose, each with its reason (decision 6).
- A4: the audit's remaining blind spots are recorded (decision 6, "After this plan").
- A5: the tests' second owner is created later than any real clock reaches, not at a fixed date (decision 3).
- A6: rebuilt and replayed.
- Optional hardening taken:
  - O1: the migration functions begin their transactions `IMMEDIATE` themselves (decision 9);
  - O2: a committed test migrates a real 3b-ii database, opened in `run_collector`'s order (decision 4);
  - O3: the store's second-owner test reconciles the owner's own host naming another owner's session (decision 5).

  O4 (store triggers) and O5 (refusing two owners) were not taken; recorded in decisions 4 and 3 and in "After this plan". O6 (a second owner over HTTP and the host socket) was not taken either.

1. **The owner exists from the first start; setup sets it up (amendment to kernel §1.1, §3.1 and umbrella §7.2).** This answers 3b-ii's open question.
   - **The question:** `up` mints a pairing code, and its host enrolls, before setup creates any owner. The `hosts` and `pairing_codes` rows written then must carry an owner.
   - **Choice:** the kernel's migration 3 creates the owner when `owners` is empty: `owner-` and 16 random hex digits, the form setup used. Every database at that version has an owner, whatever opens it first and whenever. An owner already there was made by setup, and gets `set_up_at = created_at`.
     - `owners.set_up_at` (NULL until setup) is what "set up" means now.
     - `set_up` marks it with `UPDATE owners SET set_up_at = ? WHERE id = ? AND set_up_at IS NULL`, and checks that one row changed. Of two racing setups, one marks the owner and the other answers `AlreadySetUp`.
     - `is_set_up()` reads `set_up_at`, no longer "an owner exists".
     - `Operator::owner_id()` returns `&str`: the owner, set up or not. Before, it was `Result<Option<String>>`.
   - **What changes with it:** every path that read "there is an owner" as "set up" now reads `is_set_up()`:
     - `issue_setup_token` and `set_up` (unchanged, through `is_set_up`);
     - `reset_password` and `reset_public_url`, which answer `NotSetUp` before setup;
     - `open_session`, which inserts nothing before setup because the owner has no password for its `EXISTS`.

     `a_password_reset_replaces_the_password_and_ends_every_session` and `a_public_url_reset_replaces_the_cached_origin_and_ends_every_session` already assert `NotSetUp` before setup, and are the net. Revert-probe 2 of Task 2 shows one catching it.
   - **Alternatives:**
     - **`owner_id` nullable on `hosts` and `pairing_codes`, filled in by setup's transaction.** Every query on them would need `owner_id = ? OR owner_id IS NULL` until setup: `check_hello` for `up`'s host, `enroll` for its code. A row of nobody's would be claimable by whoever sets up, and in a teams future, by the first of several. It also leaves `NOT NULL` off for good.
     - **A fixed single-owner id (`'owner'`) until teams exist.** Simplest to write, but setup has minted random ids since 3b-i, so set-up databases would need their owner renamed in every table. Every filter would compare against a constant, and teams would inherit a migration that splits it.
   - **Cost if wrong:** an owner row with no password exists from the first start. It has no login method: `open_session` needs a password `EXISTS`, and the admin socket was already operator-equivalent before setup (3b-ii decision 5). Undoing it would mean making `owners.id` at setup again, and rewriting the rows written before setup to it.
   - The spec text "First start with an empty database: generate a setup token…" (kernel §3.1) still holds. Umbrella §7.2's "a one-time setup link … to create the owner account" now completes an account the first start made. That is the amendment.
2. **Each component binds to the database's owner when it opens, not per request.**
   - **Choice:** `db::kernel_owner(conn)` runs the kernel's migrations and returns `SELECT id FROM owners ORDER BY created_at, id LIMIT 1`. `Operator`, `Hosts` and `Store` each call it in `init`, keep the result, and name it in every query.
     - It is the one query that does not filter by the owner, because it finds the owner. It lives in `db.rs`, which the audit does not read (decision 6).
     - Components on one file therefore agree, whichever opens first. `run_collector` opens the store first. `the_store_and_the_kernel_agree_on_the_owner_whichever_opens_first` pins it.
     - `Authenticated::owner_id` is now the operator's owner, not a column read back. The audit forbids reading the owner column for its value (decision 6).
   - **What it protects:** a row of another owner's, in the same file, is invisible to every method and unchanged by it. That covers the browser API through the operator, the host WebSocket through the registry, and the admin socket. A second owner's session cookie fails `authenticate`, so no request runs as that owner.
   - **What it does not do:** serve two owners from one collector. Teams would thread the owner from the request: from `Authenticated` on operator routes, from the host's row on the host socket. Every statement already has the placeholder; only the value's source would move.
   - **Alternatives:** thread an `owner: &str` through every method now, from `Authenticated` and the hello. That touches every signature of the three components and about 580 call sites in tests (330 in the store's own), for an isolation v1 never exercises (umbrella §15: teams are later).
   - **In-memory components** (`open_in_memory`, the tests' default) each get their own database, and so their own owner. Nothing compares owners across components, so nothing changes for them. No constructor's signature changes.
   - **Cost if wrong:** teams turn the bound field into a parameter. The SQL stays as it is.
3. **Which owner, if there were several.** (amended after the security review of 2026-10-01)
   - The oldest, by `created_at`, then `id`. v1 has exactly one. A second exists only when written straight into the database, as the tests do; a binary that makes them will have a newer schema, which this one refuses (kernel §1).
   - **The tests' second owner has a later `created_at` than any real clock** (A5): `OTHER_CREATED_AT = i64::MAX`, a constant in each test file that writes it, for `created_at` and `set_up_at`. Migration 3 stamps the real owner with SQLite's `unixepoch()`, so a fixed date (1 900 000 000 before the review) would one day be earlier than the real owner, and the second owner would become the database's. The review proved it with 1 700 000 000; Task 3's revert-probe repeats it.
   - **Alternative (O5, not taken):** refuse to open a database with two owners. Anyone who can write the database owns everything in it already, the schema version guards against a newer binary's data, and the tests that reopen after writing a second owner would have to change.
   - **Cost if wrong:** none in v1.
4. **The schema: how each table gets `owner_id`.**
   - **`hosts` and `pairing_codes`** (kernel migration 4) are rebuilt, then filled with the owner, as `owner_id TEXT NOT NULL REFERENCES owners(id)`. SQLite refuses `ADD COLUMN … NOT NULL` without a non-NULL default, and `ADD COLUMN … REFERENCES` with one; checked against the bundled 3.53.2. Nothing references either table, so the rebuild runs inside the migration's transaction with foreign keys on.
   - **The sessions store's six tables** (store migration 7) get `owner_id TEXT NOT NULL DEFAULT ''`, then the owner. No foreign key:
     - a `REFERENCES` column could only be added nullable;
     - a rebuild of six tables that reference each other needs `PRAGMA foreign_keys = OFF`, which a migration's transaction cannot set.

     The default names no owner, so a row written without one fails closed: no query finds it. The audit checks that every `INSERT` names `owner_id` (decision 6).
   - **The store runs the kernel's migrations first** (`Store::init`). Its backfill reads the owner from `owners`, which therefore exists whichever component opens a database first. `run_collector` opens the store first. The kernel's tables already shared `hennery.db` with the store; now the store depends on them.
   - **Rows already there** get the database's owner: one `UPDATE` per table, as 3b-i decision 1 foresaw. For a 3b-ii database left before setup, that is the owner migration 3 just made.
   - **No index on `owner_id`.** With one owner, an index on it selects every row.
   - **`schema_versions` has no `owner_id`.** It is migration bookkeeping, not data. `owners` names its owner in `id`.
   - **A real 3b-ii database, opened in `run_collector`'s order** (O2; amended after the security review of 2026-10-01): `a_3b_ii_database_opened_in_the_collectors_order_has_one_owner_for_every_row`, in `store.rs`'s unit tests (the store's first six migrations are private), builds the file from the kernel's two 3b-ii migrations and the store's first six, verbatim, with a row in each of the eight older tables, set up and not. It opens the store, then the registry, then the operator: kernel 2 to 4 and store 6 to 7 in one start, store first, as every development install does. One owner, the same for all three; every row carries it and is found; the old password works, or setup does.
   - **Cost if wrong:** a missing foreign key lets the store's rows name an owner that does not exist. Nothing in v1 writes another owner, and those rows would be invisible. Triggers could enforce it (O4: `BEFORE INSERT`/`UPDATE`, `RAISE(ABORT)` when a row's owner differs from its session's); not taken for v1, revisit with teams.
5. **What filtering means in the store.**
   - Every statement names the owner. That includes those on child rows keyed by their own ids (`turns` by `turn_id`, `pending` by `pending_id`, `events` by `event_id`), and the joins between them: `ON … AND q.owner_id = p.owner_id`.
   - **Reads** of another owner's session, turn, question or event find nothing (`None`, empty, `NotFound`).
   - **Writes** for another owner's session write nothing. `collector_event` inserts only `WHERE EXISTS` the session is the owner's, and fails otherwise. `ingest` checks the session first and fails. So `record_park_request` and `record_close_request` on such a session fail, and `close_now` changes nothing.
   - **Upserts** guard their update: `ON CONFLICT(session_id) DO UPDATE … WHERE session_catalog.owner_id = excluded.owner_id`.
   - **The owner comes from a parameter**, never copied from a row. An `INSERT … SELECT` copying `owner_id` from a row the `WHERE` failed to filter would carry that row's owner along.
   - The API already checked a session before writing for it, and the host socket already checked that a session is its host's (`ws.rs`). These are a second line, and the test of decision 6's second half.
   - **The owner's own host naming another owner's session** (O3; amended after the security review of 2026-10-01): `reconcile_host("host-a", [session-b])` leaves the other owner's rows as they were, and reconciles the owner's `session-a` as one its host no longer has. `another_owners_sessions_are_invisible_to_the_store` pins it.
   - **Alternatives:** filter only the statements a public method starts with, and trust the child keys after them. Fewer edits, but "every query filters by it" would then rest on argument, not on a test.
   - **Cost if wrong:** none known. It only narrows what a statement can reach.
6. **How "every query filters" is proven (3b-ii's A10).** (amended after the security review of 2026-10-01: A1–A4)
   - **The audit** (`crates/hennery-testkit/tests/owner_filter.rs`):
     - It reads the source of `operator.rs`, `hosts.rs` and `store.rs` (`include_str!`), without their unit tests (`#[cfg(test)] mod tests` at the end of the file), whose fixtures write raw rows on purpose.
     - It takes every string literal that begins with `SELECT`, `INSERT`, `UPDATE`, `DELETE` or `WITH`, and resolves `{CONST}`s such as `HOST_COLUMNS` and `PENDING_COLUMNS` from the file's own `const …: &str`.
     - It prepares each statement on a migrated `hennery.db` under rusqlite's authorizer, which reports every table and column the statement reads, inserts into, updates or deletes from.
   - **The rules:**
     - Every table touched must have its owner column read (`owner_id`; `id` for `owners`), in a `WHERE`, a join or a subquery.
     - **At least one owner column must be compared with a parameter** (A1): `owner_id = ?N` or `?N = owner_id`, qualified (`p.owner_id`) or not, or `id = ?N` when the statement names `owners`. The statement is split on whitespace, `(`, `)` and `,`, and the three tokens looked for either way round. A plain `INSERT … VALUES` (no `SELECT`) is exempt: it names the owner among its columns. Before the review a join comparing two owner columns (`s.owner_id = q.owner_id`) counted as reading them, so `answers_to_send` with its `q.owner_id = ?2` made always true passed the audit (the review's probe); now it fails.
     - Every `INSERT` must name `owner_id` among its columns.
     - The owner column is never read for its value: not returned, and not copied by an `INSERT … SELECT`. Otherwise a read in the select list would pass for a filter.
     - Reads SQLite makes on its own are not the statement's, and are skipped: a foreign key's check of its parent (a table the statement does not name), and an upsert's look-up of its conflict target: the table it inserts into, when it changes nothing there **and does not read it with `FROM` or `JOIN`** (A2). Before the review an `INSERT … SELECT` from its own target, unfiltered, passed as a conflict-target look-up.
   - **It fails** on any statement that breaks a rule. It also fails on one that does not prepare, on a `{CONST}` it cannot resolve, and on a file with fewer statements than it has now (17, 13, 77), so an extractor that broke cannot pass by finding nothing.
   - **Every file with SQL is audited or exempt** (A3): `every_file_with_sql_is_audited_or_exempt` walks every `*.rs` under `crates/*/src` (from `CARGO_MANIFEST_DIR`, `std::fs` and `Path` only) and fails on a file whose code, unit tests left out, holds a statement and is in neither `SOURCES` nor `EXEMPT`. Each `EXEMPT` entry carries its reason, and an entry whose file is gone fails too:
     - `hennery-kernel/src/db.rs`: `kernel_owner`'s query finds the owner; the rest is the migrations' bookkeeping and their unit tests;
     - `hennery-host/src/outbox.rs`: the host's own database, on the host's machine, not `hennery.db`.
   - `the_audit_catches_a_query_without_the_owner` pins the rules on statements written to break each one, and the extractor on comments, char literals and raw strings.
   - **What it cannot see** (A4), each verified by the review to pass it:
     - a filter that is wrong rather than missing: `OR owner_id = ?`, or a self-comparison `owner_id = owner_id` beside a real comparison elsewhere;
     - the owner column returned under an alias (`SELECT owner_id AS o …`): the "returned" rule reads result names;
     - the owner column read as an expression in the select list (`SELECT phc, owner_id = ?1 FROM …`) with no `WHERE` on it. A1 catches that only when the statement has no other owner comparison: the expression is itself a comparison with a parameter.

     The second-owner tests are the net for these: another owner's rows, written the same way as the owner's own (the control), are found by none of the component's methods and changed by none.
   - **Not audited:**
     - `db.rs` and `outbox.rs`, the two `EXEMPT` entries above;
     - `schema.rs` and the store's `MIGRATIONS`: the backfill writes every row on purpose (they are statements of the `ALTER`/`CREATE`/`UPDATE … SET owner_id` kind inside migration strings, which the extractor does not take, since none begins with a statement's verb);
     - unit tests inside a source file.
   - **Alternatives:**
     - A textual check (`owner_id` appears in the literal). It cannot tell `SELECT owner_id` from `WHERE owner_id = ?`, nor one table of a join from another.
     - A check at runtime, an authorizer on every production connection. It has no hook at the end of a statement's preparation to judge the whole, so it cannot refuse a statement for what it lacks.
   - **Cost if wrong:** a new file with SQL fails the audit until it is added to `SOURCES`, or to `EXEMPT` with a reason (A3). What the audit cannot see (above) rests on the second-owner tests.
7. **Host keys stay unique across owners.**
   - `hosts.public_key` keeps its table-wide `UNIQUE`: one key, one host, one owner.
   - `insert_host` looks for the key among the owner's hosts only, so a key paired under another owner is not reported as `AlreadyPaired` (that would name the other owner's host). The insert then fails on the constraint, an internal error, and the code is not spent.
   - Nothing in v1 can reach it. `another_owners_hosts_and_codes_are_invisible_to_the_registry` pins that the error spends nothing.
   - **Alternative:** `UNIQUE(owner_id, public_key)`: one machine could pair with two owners. Left for teams to decide.
   - **Cost if wrong:** a 500 where a 409 would be kinder, unreachable in v1. For teams (from the review): with any valid code, the 500 against a 409 or a 201 tells the caller that a key is paired under some other owner, an existence oracle. Teams must scope keys per owner or answer that case like an invalid code; recorded in "After this plan".
8. **A password reset with no password to replace fails (3b-ii's O9).**
   - `reset_password` checks that its `UPDATE password_credentials` changed exactly one row, inside the transaction. Otherwise it fails ("the owner has no password to reset") and rolls back before the sessions are deleted: no session ends, and the limiters stay as they were.
   - Unreachable before 3c, where a passkey-only owner may have no password row. 3c decides whether a reset should then add one.
   - **Cost if wrong:** a reset of a passkey-only owner fails with that message, through the admin socket's `Failed`.
9. **A migration reads its version inside its transaction (3b-i's note).** (amended after the security review of 2026-10-01: O1)
   - `migrate` and `migrate_component` loop: each step opens its transaction, which holds the write lock from its start, and reads the version under it. It then applies the next step, or commits and returns when none is left.
   - **`IMMEDIATE` is asked for in the functions themselves** (O1): `conn.transaction_with_behavior(TransactionBehavior::Immediate)`, not the connection's default. Both functions are `pub`, and a caller could pass a connection `configure` never touched, on which `transaction()` is deferred: its version read would take no lock, and its write would then fail `database is locked`, or, before Task 1, run the step twice. The race tests now migrate on such a connection (`unconfigured`: a busy timeout, no `IMMEDIATE`), so they fail without O1 too (Task 1's revert-probe).
   - A version read before the lock could be stale by the time the lock is held, and the step would run twice. This matters now that the store runs the kernel's migrations too: two components, or two collectors, on one file.
   - The tests hold the write lock on one connection, start a migration on another, apply the step meanwhile, then commit. The racing migration must see the step done. On the old code it applies it again and fails "table … already exists".
   - The review confirmed the rest: `migrate`'s last pass drops an empty `IMMEDIATE` transaction (a rollback) and `migrate_component`'s commits one; both are harmless.
   - **Alternative:** read the version outside a transaction, return at once when it is current, and re-read it under the lock only when it is behind. That is race-free too and takes no lock on the common path. Not taken: two reads of one value, for a cost paid only at open; a reviewer may prefer it.
   - **Cost if wrong:** every open now takes the write lock, even on a current schema; the store takes it twice, for the kernel's component and its own. Behind another writer, an open waits up to the 5 s busy timeout. The collector opens its three components once, at start.

/// Every string literal in `source`, in order, skipping comments and char
/// literals. Enough of Rust's lexer for these files: plain and raw
/// strings, the common escapes and line continuations.
fn string_literals(source: &str) -> Vec<String> {
    let s: Vec<char> = source.chars().collect();
    let mut out = Vec::new();
    let mut i = 0;
    while i < s.len() {
        let rest = &s[i..];
        if rest.starts_with(&['/', '/']) {
            while i < s.len() && s[i] != '\n' {
                i += 1;
            }
        } else if rest.starts_with(&['/', '*']) {
            i += 2;
            while i + 1 < s.len() && !(s[i] == '*' && s[i + 1] == '/') {
                i += 1;
            }
            i += 2;
        } else if s[i] == 'r'
            && matches!(s.get(i + 1), Some('"' | '#'))
            && (i == 0 || !(s[i - 1].is_alphanumeric() || s[i - 1] == '_'))
        {
            let mut hashes = 0;
            i += 1;
            while s[i] == '#' {
                hashes += 1;
                i += 1;
            }
            i += 1;
            let mut lit = String::new();
            loop {
                if s[i] == '"' && s[i + 1..].iter().take(hashes).filter(|c| **c == '#').count() == hashes {
                    i += 1 + hashes;
                    break;
                }
                lit.push(s[i]);
                i += 1;
            }
            out.push(lit);
        } else if s[i] == '"' {
            i += 1;
            let mut lit = String::new();
            while s[i] != '"' {
                if s[i] == '\\' {
                    i += 1;
                    match s[i] {
                        'n' => lit.push('\n'),
                        't' => lit.push('\t'),
                        '\n' => {
                            while s[i + 1].is_whitespace() {
                                i += 1;
                            }
                        }
                        c => lit.push(c),
                    }
                } else {
                    lit.push(s[i]);
                }
                i += 1;
            }
            i += 1;
            out.push(lit);
        } else if s[i] == '\'' {
            // A char literal ('x', '\n', '"'), or a lifetime ('a).
            if s.get(i + 1) == Some(&'\\') {
                i += 2;
                while s[i] != '\'' {
                    i += 1;
                }
                i += 1;
            } else if s.get(i + 2) == Some(&'\'') {
                i += 3;
            } else {
                i += 1;
            }
        } else {
            i += 1;
        }
    }
    out
}

/// `const NAME: &str = "…";` in `source`, by name.
fn str_consts(source: &str) -> BTreeMap<String, String> {
    let mut out = BTreeMap::new();
    for (at, _) in source.match_indices("const ") {
        let decl = &source[at + "const ".len()..];
        let Some((name, rest)) = decl.split_once(": &str = ") else {
            continue;
        };
        if !name.chars().all(|c| c.is_ascii_uppercase() || c == '_') || !rest.starts_with('"') {
            continue;
        }
        let value = string_literals(rest).into_iter().next().expect("the const's literal");
        out.insert(name.to_string(), value);
    }
    out
}

/// The SQL statements in `source`, `{CONST}`s resolved.
fn statements(source: &str) -> Vec<String> {
    let consts = str_consts(source);
    let mut out = Vec::new();
    for lit in string_literals(source) {
        let first = lit.split_whitespace().next().unwrap_or_default();
        if !matches!(first, "SELECT" | "INSERT" | "UPDATE" | "DELETE" | "WITH") {
            continue;
        }
        let mut sql = lit.clone();
        for (name, value) in &consts {
            sql = sql.replace(&format!("{{{name}}}"), value);
        }
        assert!(!sql.contains('{'), "an unresolved constant in {lit:?}");
        out.push(sql);
    }
    out
}

/// What preparing `sql` touches: per table, the actions and the columns
/// read; and the columns it returns.
#[derive(Debug, Default)]
struct Touched {
    read: BTreeMap<String, BTreeSet<String>>,
    changed: BTreeSet<String>,
    inserted: BTreeSet<String>,
    returned: Vec<String>,
}

fn touched(conn: &rusqlite::Connection, sql: &str) -> Touched {
    let log: Arc<Mutex<Touched>> = Arc::default();
    let sink = log.clone();
    conn.authorizer(Some(move |ctx: AuthContext<'_>| {
        let mut t = sink.lock().unwrap();
        match ctx.action {
            AuthAction::Read {
                table_name,
                column_name,
            } => {
                t.read
                    .entry(table_name.to_string())
                    .or_default()
                    .insert(column_name.to_string());
            }
            AuthAction::Update { table_name, .. } | AuthAction::Delete { table_name } => {
                t.changed.insert(table_name.to_string());
            }
            AuthAction::Insert { table_name } => {
                t.inserted.insert(table_name.to_string());
            }
            _ => {}
        }
        Authorization::Allow
    }))
    .unwrap();
    let prepared = conn
        .prepare(sql)
        .map(|stmt| stmt.column_names().into_iter().map(String::from).collect());
    conn.authorizer(None::<fn(AuthContext<'_>) -> Authorization>).unwrap();
    let returned = prepared.unwrap_or_else(|err| panic!("{err}: {sql}"));
    let mut touched = Arc::try_unwrap(log).unwrap().into_inner().unwrap();
    touched.returned = returned;
    touched
}

/// The column that names a table's owner.
fn owner_column(table: &str) -> &'static str {
    if table == "owners" { "id" } else { "owner_id" }
}

/// Whether an `INSERT INTO table(…)` in `sql` names `owner_id`.
fn inserts_owner(sql: &str, table: &str) -> bool {
    let Some((_, after)) = sql.split_once(&format!("INSERT INTO {table}(")) else {
        return false;
    };
    let columns = after.split(')').next().unwrap_or_default();
    columns.split(',').any(|c| c.trim() == "owner_id")
}

/// Whether `sql` compares an owner column with a parameter: `owner_id = ?N`
/// or `?N = owner_id`, qualified (`p.owner_id`) or not, or `id = ?N` when it
/// names `owners`. A join that compares two owner columns ties the rows to
/// each other, not to the owner (3b-iii review, A1).
fn compares_owner_with_a_parameter(sql: &str) -> bool {
    let tokens: Vec<&str> = sql
        .split(|c: char| c.is_whitespace() || matches!(c, '(' | ')' | ','))
        .filter(|t| !t.is_empty())
        .collect();
    let names_owners = tokens.contains(&"owners");
    let column = |t: &str| {
        let name = t.rsplit('.').next().unwrap_or(t);
        name == "owner_id" || (names_owners && name == "id")
    };
    let parameter = |t: &str| t.len() > 1 && t.starts_with('?') && t[1..].chars().all(|c| c.is_ascii_digit());
    tokens
        .windows(3)
        .any(|w| w[1] == "=" && ((column(w[0]) && parameter(w[2])) || (parameter(w[0]) && column(w[2]))))
}

/// Why `sql` does not filter by the owner, if it does not. A read of the
/// owner column counts as filtering by it, so the column is never read for
/// its value: not returned, and not copied by an `INSERT … SELECT` (the
/// owner comes from a parameter there); and one owner column at least is
/// compared with a parameter. What this cannot see (3b-iii review, A4): a
/// filter that is wrong (`OR`, `owner_id = owner_id`); the owner column read
/// for its value under an alias (`owner_id AS o`) or as an expression in
/// the select list (`owner_id = ?1` there) beside another comparison. The
/// second-owner tests are the other half.
fn problems(conn: &rusqlite::Connection, sql: &str) -> Vec<String> {
    let t = touched(conn, sql);
    let mut out = Vec::new();
    let tables: BTreeSet<&String> = t.read.keys().chain(&t.changed).collect();
    for table in &tables {
        let read = t.read.get(*table).cloned().unwrap_or_default();
        if !read.contains(owner_column(table)) {
            out.push(format!("{table} is touched without reading {}", owner_column(table)));
        }
    }
    for table in &t.inserted {
        if !inserts_owner(sql, table) {
            out.push(format!("an INSERT INTO {table} names no owner_id"));
        }
    }
    if t.returned.iter().any(|c| c == "owner_id") {
        out.push("it returns owner_id: compare the column, do not read it back".into());
    }
    if sql.trim_start().starts_with("INSERT")
        && let Some((_, select)) = sql.split_once("SELECT")
        && select.split("FROM").next().unwrap_or_default().contains("owner_id")
    {
        out.push("its INSERT … SELECT copies owner_id: take it from a parameter".into());
    }
    let values_only = sql.trim_start().starts_with("INSERT") && !sql.contains("SELECT");
    if !tables.is_empty() && !values_only && !compares_owner_with_a_parameter(sql) {
        out.push("no owner column is compared with a parameter".into());
    }
    out
}

/// Every row of `owner`'s in `tables`, as stored.
fn rows_of(conn: &rusqlite::Connection, tables: &[&str], owner: &str) -> Vec<Vec<Value>> {
    let mut out = Vec::new();
    for table in tables {
        let column = if *table == "owners" { "id" } else { "owner_id" };
        let mut stmt = conn
            .prepare(&format!("SELECT * FROM {table} WHERE {column} = ?1 ORDER BY rowid"))
            .unwrap();
        let width = stmt.column_count();
        let rows = stmt
            .query_map([owner], |r| (0..width).map(|i| r.get::<_, Value>(i)).collect())
            .unwrap();
        out.extend(rows.map(Result::unwrap));
    }
    out
}

/// owner. Another owner's host and pairing code, in the same database,
/// are neither seen nor changed: its host's valid proof is refused like an
/// unknown host's, it is not listed and cannot be revoked, and its code
/// pairs nothing. The real owner's, written the same way, work (the
/// control). The other owner's key cannot be paired again under this
/// owner either: keys are unique across owners (3b-iii decision 7).

fn another_owners_hosts_and_codes_are_invisible_to_the_registry() {
    let dir = tempfile::tempdir().unwrap();
    let db = dir.path().join("hennery.db");

    write_host(&conn, OTHER, "host-b2", 2);
    write_code(&conn, OTHER, "BBBB-BBBB");
    write_host(&conn, hosts.owner_id(), "host-a1", 1);
    write_code(&conn, hosts.owner_id(), "AAAA-AAAA");
    let theirs = rows_of(&conn, HOST_TABLES, OTHER);
    let nonce = [7u8; 32];

    assert_eq!(
        hosts
            .check_hello("host-a1", &nonce, "1.0", &proof(1, &nonce, "host-a1"))

            .unwrap(),
        HelloCheck::BadProof

    assert_eq!(hosts.host("host-b2").unwrap(), None);
    let listed: Vec<String> = hosts.list().unwrap().into_iter().map(|h| h.id).collect();
    assert_eq!(listed, ["host-a1"]);
    assert_eq!(hosts.revoke("host-b2", NOW).unwrap(), Revoke::NotFound);

        EnrollOutcome::Enrolled { .. }

    assert!(hosts.is_revoked("host-a1").unwrap());
}

/// Whether `sql` names `table`, as a whole word.
fn names(sql: &str, table: &str) -> bool {

        .any(|(at, _)| !word(sql[..at].chars().next_back()) && !word(sql[at + table.len()..].chars().next()))

/// Every `*.rs` under `dir`, as paths relative to `root` with `/` between
/// their parts.
fn rust_files(root: &Path, dir: &Path, out: &mut Vec<String>) {
    let mut entries: Vec<_> = std::fs::read_dir(dir).unwrap().map(|e| e.unwrap().path()).collect();
    entries.sort();
    for path in entries {
        if path.is_dir() {
            rust_files(root, &path, out);
        } else if path.extension().is_some_and(|e| e == "rs") {
            let parts: Vec<String> = path
                .strip_prefix(root)
                .unwrap()
                .components()
                .map(|c| c.as_os_str().to_string_lossy().into_owned())
                .collect();
            out.push(parts.join("/"));
        }
    }
}
