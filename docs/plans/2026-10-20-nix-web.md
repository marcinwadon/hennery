# The web UI's Nix derivation, embedded in the package (plan 7e-ii-b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ] `) syntax for tracking.

**Goal:** `nix build` gives a `hennery` that embeds the real web UI (distribution spec §4.3; plan 4b's hand-off to 7e-ii):
- the web build is a derivation of its own, on nixpkgs-web, with its dependencies from one fixed-output `fetchPnpmDeps` whose hash is the same on every system;
- the package passes it to the kernel's build script through `HENNERY_WEB_DIST`, with `HENNERY_WEB_REQUIRE=1`, so a Nix build fails rather than embed the placeholder page;
- a flake check proves the built binary embeds the UI, and the binary keeps no reference to the web build;
- a script rewrites the dependency hash after a change to `web/pnpm-lock.yaml`.

Nothing is published.

**Architecture:**
- `nix/web.nix` (new): `stdenvNoCC.mkDerivation` with nixpkgs-web's `fetchPnpmDeps` (`fetcherVersion = 4`, `pnpm_12`) and `pnpmConfigHook`, then `pnpm build` offline. Its output is `web/dist`: `index.html`, `assets/`, and `public/`'s files. It references no store path (`allowedReferences = [ ]`).
- `nix/package.nix`: the package build sets `HENNERY_WEB_DIST` and `HENNERY_WEB_REQUIRE`, and disallows a reference to the web build. The new check `web-ui` runs `packaging/check-web-ui.sh` on the binary. `buildDepsOnly`, clippy, fmt and audit are unchanged and never build the web UI.
- `flake.nix`: `webUi` from nixpkgs-web, passed to `nix/package.nix`; `packages.web`; the dev shells take the web build's pnpm.
- `packaging/update-web-hash.sh` (new): rewrites the hash in `nix/web.nix`.
- `.github/workflows/nix.yml` is unchanged: `nix flake check` already builds every check.

**Tech Stack:** Nix flakes; nixpkgs-web at `e158d9e` (the same revision as `nixpkgs`): `fetchPnpmDeps` with fetcher versions 3 and 4, `pnpm_12` 12.3.4 (pnpm's Rust build), Node 24; crane 0.24.0 (unchanged); POSIX `sh`.

**Spec:** [`docs/specs/2026-09-26-distribution-design.md`](../specs/2026-09-26-distribution-design.md) §4.3:

**Cross-lane:**

- **The one cost for the frontend lane:** a PR that changes `web/pnpm-lock.yaml` must also run `sh packaging/update-web-hash.sh` and commit `nix/web.nix`. Otherwise the `nix` job fails with a hash mismatch in `hennery-web-pnpm-deps`.

## Decisions this plan makes where the spec is silent

1. **nixpkgs-web builds it, with `pnpm_12` named.**
   - The web build uses the nixpkgs input the dev shell takes Node and pnpm from (plan 4b), so a Nix build and `pnpm build` in the dev shell use the same tools.
   - `pnpm_12`, not `pnpm`: a nixpkgs-web bump that moves the `pnpm` alias to 13 does not silently change the store layout and the hash. The lock (`lockfileVersion: '9.0'`) does not record which major wrote it.
   - The dev shells take `webUi.pnpm`, the same package, so they cannot drift from the build (the review's O1). Today it is the same store path as `web.pnpm`, so the dev shell's derivation is unchanged.
2. **`fetcherVersion = 4`.**
   - It is §4.3's version, and the only one nixpkgs-web's fetcher accepts for pnpm 11 and newer. It supports `[ 3 4 ]`, and 3 throws for pnpm ≥ 11 (`pkgs/build-support/node/fetch-pnpm-deps/default.nix`).
   - D-1 holds: a version nixpkgs removes fails evaluation loudly, with nixpkgs' own message, and this plan keeps no second nixpkgs to stay on it.
3. **One hash for every system, and no `supportedArchitectures` (spec amendment).**
   - The fetcher runs `pnpm install --force --ignore-scripts --frozen-lockfile`. With `--force`, pnpm fetches every optional package whatever its `os`, `cpu` and `libc`: the fetch took aix, netbsd, win32 and wasm32 packages too.
   - A probe with a `pnpm-workspace.yaml` declaring `supportedArchitectures` (linux/darwin × x64/arm64 × glibc) fetched the same set, so the file would change nothing. It is not added, and nothing under `web/` changes.
   - **Verified:** the same hash on aarch64-darwin (locally) and x86_64-linux (#94's ubuntu job built the fixed-output derivation with no mismatch). aarch64-linux is built by no runner.
   - **Cost:** the store is about 380 MB compressed, every platform's binaries, fetched from the npm registry on every cold CI run. #94's ubuntu job took 9.6 minutes against main's 6.5 to 11.5; the web part took about 70 seconds of it. On `bb468da` the jobs took 7.7 minutes (ubuntu) and 11.9 minutes (macOS, against main's 11.7 to 12.2): the macOS runners, the fleet's bottleneck, pay nothing noticeable.
4. **A workaround in the fetcher's fixup: `v11/links` is dropped.**
   - pnpm 12 keeps every package unpacked under `<store>/v11/links`, beside the content-addressed `files/` and `index.db` it is made from.
   - The fetcher's fixup runs `jq --sort-keys` over every `*.json` in the store, so under pnpm 12 it rewrites package files. It stops at the first one that is not strict JSON: `@tybys/wasm-util`'s `dist/tsdoc-metadata.json`, which starts with `//` comments and is bundled in `@tailwindcss/oxide-wasm32-wasi`. That fails with `jq: parse error: Invalid numeric literal at line 1, column 3`.
   - The fix: `preFixup` (passed through to the fixed-output derivation, and run before that loop) removes `links`. The offline install rebuilds `links` from `files` and `index.db` (probed). It halves the store, and no package file is edited.
   - `${storePath:?}` fails if the fetcher's variable is ever renamed or empty, rather than running `rm -rf /v11/links`. A missing `v11` directory, a new store layout, fails with "no v11 store: revisit this workaround" (the review's O4).
   - **When to remove it:** when nixpkgs' fixup skips `links`. The hash changes then, and the comment in `nix/web.nix` names the revision.
5. **The source is all of `web/` except build and test outputs** (`node_modules`, `dist`, `test-results`, `playwright-report`, `*.tsbuildinfo`).
   - A file the frontend lane adds (a config, a new directory) needs no change under `nix/`. A list of named files would break the Nix build on the lane's PR instead.
   - The dependency hash does not depend on the source, only on what the lock names, so an edit under `web/src` rebuilds the UI and refetches nothing.
6. **The variables are set on the package build only.**
   - `HENNERY_WEB_DIST = "${webUi}"` and `HENNERY_WEB_REQUIRE = "1"` are in the package's attributes, not in `common`.
   - `buildDepsOnly`, clippy, fmt and audit do not build the web UI. Clippy's kernel build embeds the placeholder, as every lane's `cargo clippy` does. `nix derivation show -r .#checks.<system>.{clippy,fmt,audit}` names no `hennery-web`.
   - Nix is the one switch: no `nix build` of the package can embed the placeholder, because `HENNERY_WEB_REQUIRE=1` fails it first (probed).
7. **What proves the embedding.**
   - **The `web-ui` check** runs plan 4b's `packaging/check-web-ui.sh` on the package's binary. It fails if the placeholder's marker is present, or if the binary cannot be read.
   - **The web build checks itself:** `index.html` must load an `assets/*.js` the build made (the review's O5). An empty or stale `dist` fails there, before the package is built.
   - **References:**
     - `allowedReferences = [ ]` on the web build (the review's A3): an embedded file naming a store path fails the build;
     - `disallowedReferences = [ webUi ]` on the package: the binary embeds the UI, so it never keeps the web build in its closure. Today the closure is the binary, OpenSSL and libiconv (24 MB).
8. **A shell script rewrites the hash, rather than a flake app or a CI step.**
   - `sh packaging/update-web-hash.sh`, from anywhere in the repo:
     1. it writes a placeholder hash;
     2. builds `.#web.pnpmDeps`;
     3. takes the `got:` hash from Nix's mismatch;
     4. writes it back.
   - On any other failure, or when it is interrupted (TERM or INT), `nix/web.nix` gets its old hash back (the review's A4). It prints which hash changed, or that the hash was already right.
   - A flake app would run the same commands from the store, against the caller's working tree. A script beside the packaging checks is simpler to read and needs no evaluation.
   - **No hint step in `nix.yml`:** the mismatch names `hennery-web-pnpm-deps`, and the first lines of `nix/web.nix` name the script. Leaving `nix.yml` alone keeps 7e-ii-a's rebase trivial.
9. **`nix.yml` is unchanged.**
   - `nix flake check` builds every check, `web-ui` included, on both systems, and `nix run . -- --version` runs the package that embeds the UI.
   - The job's 30-minute timeout has room (decision 3's times).
   - There is no binary cache, so every cold run refetches the dependencies and checks the hash. That is what makes the hash a CI-checked claim (the review's A5, under "After this plan").
10. **`packages.web`** is exposed, so `nix build .#web` and `.#web.pnpmDeps` (which the script uses) can be built alone.

## Global Constraints

- **The dev shell's checks are unaffected:** no Rust file changes, and the dev shells' derivations are unchanged (decision 1). After every task, `nix develop -c cargo fmt --all --check` passes.
- **`flake.lock` does not change.** Check: `git diff --stat origin/main -- flake.lock` is empty.
- **Flakes ignore untracked files:** `git add` (or `git add -N`) a new file before any `nix` command reads it.
- **Nothing publishes:** no cache push, no token, no new permission. The fixed-output derivation reads the public npm registry only, at the lock's integrities (`web/.npmrc` names the registry).
- **Tests never fetch the npm registry:** no Rust or Vitest test changes. The fixed-output fetch is a Nix build, not a test.
- **Probes that run pnpm outside Nix** pass the store and cache directories as `pnpm_config_store_dir`/`pnpm_config_cache_dir`, and never `pnpm config set`, which writes the user's own pnpm configuration.
- **`web/` is the frontend lane's:** nothing under it changes. The probes that edit `web/package.json` or `web/pnpm-lock.yaml` undo that with `git checkout -- web/package.json web/pnpm-lock.yaml`, and only once those files hold nothing but the probe's edit.

## Review Focus

1. **A frontend PR that changes `web/pnpm-lock.yaml` and not the hash.**
   - Expected: the `nix` job fails with a hash mismatch in `hennery-web-pnpm-deps`, and `sh packaging/update-web-hash.sh` fixes it.
   - With a warm local store, the stale output is reused, and the build fails with `ERR_PNPM_NO_OFFLINE_TARBALL` instead.
   - Probed (Task 1, Step 4).
2. **A Nix build that would embed the placeholder.**
   - Expected: it fails, at the kernel's build script (`HENNERY_WEB_REQUIRE=1`). If that were removed, it would fail at the `web-ui` check.
   - Both probed (Task 2, Step 3).
3. **A nixpkgs-web bump.**
   - Expected: the hash may change, from a fetcher fix or a new pnpm 12. The script updates it.
   - A new store layout, or a fetcher that no longer exposes `storePath`, fails loudly in `preFixup`. `pnpm_12` stays named, and a removed fetcher version fails evaluation (D-1).
4. **A user running `nix run github:marcinwadon/hennery`.**
   - Expected: the UI is served. The `web-ui` check and the package's run step cover that in CI on both systems.

- [ ] **Step 1: The derivation**

  Create `nix/web.nix`:

  ```nix
  # The web UI's build (plan 7e-ii-b, distribution spec §4.3), from
  # nixpkgs-web: the Node and pnpm the dev shell builds it with. The package
  # embeds this output through `HENNERY_WEB_DIST`.
  #
  # The dependencies are one fixed-output derivation, fetched from the npm
  # registry by `fetchPnpmDeps` at the lock's integrity hashes. Its own hash
  # is the same on every system: the fetcher installs with `--force`, which
  # takes every platform's optional packages, not only this system's. The
  # build itself is offline, from that store.
  #
  # After any change to web/pnpm-lock.yaml: `sh packaging/update-web-hash.sh`.
  { pkgs }:
  let
    inherit (pkgs) lib;
    # The major `web/pnpm-lock.yaml` was written by. A new major is a
    # deliberate change here, and a new dependency hash.
    pnpm = pkgs.pnpm_12;
    # Everything under `web/` that is not a build or test output, so a file
    # the frontend adds needs no change here.
    src = lib.fileset.toSource {
      root = ../web;
      fileset = lib.fileset.difference ../web (
        lib.fileset.unions [
          (lib.fileset.maybeMissing ../web/node_modules)
          (lib.fileset.maybeMissing ../web/dist)
          (lib.fileset.maybeMissing ../web/test-results)
          (lib.fileset.maybeMissing ../web/playwright-report)
          (lib.fileset.fileFilter (file: file.hasExt "tsbuildinfo") ../web)
        ]
      );
    };
  in
  pkgs.stdenvNoCC.mkDerivation (finalAttrs: {
    pname = "hennery-web";
    inherit ((lib.importJSON ../web/package.json)) version;
    inherit src;

    pnpmDeps = pkgs.fetchPnpmDeps {
      inherit (finalAttrs) pname version src;
      inherit pnpm;
      # The only version this nixpkgs' fetcher takes for pnpm 11 and newer
      # (D-1: a version nixpkgs removes fails evaluation, it is never kept).
      fetcherVersion = 4;
      # A workaround for the fetcher of nixpkgs-web at e158d9e with pnpm 12:
      # pnpm 12 keeps every package unpacked under `v11/links`, beside the
      # content-addressed `files` it is made from, and the fetcher's fixup
      # rewrites every `*.json` in the store with jq. It stops at the first
      # package file that is not strict JSON (a commented
      # `tsdoc-metadata.json`). The offline install rebuilds `links` from
      # `files`, so it is dropped before that fixup: half the size, and no
      # package file edited. Remove this once the fixup skips `links`; the
      # hash changes then.
      preFixup = ''
        [ -d "''${storePath:?}/v11" ] || { echo "no v11 store: revisit this workaround" >&2; exit 1; }
        rm -rf "''${storePath:?}/v11/links"
      '';
      # Changes with `web/pnpm-lock.yaml`: after a lock change, run
      # `sh packaging/update-web-hash.sh`. A stale hash fails CI with a hash
      # mismatch in `hennery-web-pnpm-deps`. A store that already holds the
      # old output never refetches it, so locally the build fails instead,
      # with ERR_PNPM_NO_OFFLINE_TARBALL.
      hash = "sha256-5p7sGn/gcxYo5HKokMqyUG0Y25POOVnJiNFyi8I4vxI=";
    };

    nativeBuildInputs = [
      pkgs.nodejs_24
      pnpm
      pkgs.pnpmConfigHook
    ];

    buildPhase = ''
      runHook preBuild
      pnpm build
      runHook postBuild
    '';

    installPhase = ''
      runHook preInstall
      # The page loads the entry script the build made, not a stale name. The
      # pattern is the tag Vite writes today: after a Vite upgrade, a failure
      # here may mean a new format rather than a bad build.
      entry=$(sed -n 's|.*<script type="module" crossorigin src="/\(assets/[^"]*\.js\)".*|\1|p' dist/index.html)
      if [ -z "$entry" ] || [ ! -f "dist/$entry" ]; then
        echo "dist/index.html loads no script the build made" >&2
        exit 1
      fi
      cp -r dist "$out"
      runHook postInstall
    '';

    # The build is embedded in the binary: it must name no store path.
    allowedReferences = [ ];

    # The dev shell takes the same pnpm (`flake.nix`).
    passthru = { inherit pnpm; };
  })
  ```

- [ ] **Step 3: The hash script, and the build**

  Create `packaging/update-web-hash.sh`:

  ```sh
  #!/bin/sh
  # Rewrites the web UI's dependency hash in nix/web.nix (plan 7e-ii-b), for
  # after a change to web/pnpm-lock.yaml. It builds the dependencies with a
  # placeholder hash, takes the hash Nix reports, and writes it back. On any
  # other failure nix/web.nix is left as it was.
  #
  # Usage: sh packaging/update-web-hash.sh   (from anywhere in the repo)
  set -eu

  cd "$(dirname "$0")/.."
  file=nix/web.nix
  fake=sha256-AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=
  old=$(sed -n 's/^ *hash = "\(sha256-[A-Za-z0-9+/=]*\)";$/\1/p' "$file")
  case $old in
      sha256-*) ;;
      *) echo "FAIL: no single hash line in $file" >&2; exit 1 ;;
  esac
  [ "$(printf '%s\n' "$old" | wc -l)" -eq 1 ] || { echo "FAIL: more than one hash line in $file" >&2; exit 1; }

  backup=$(mktemp)
  log=$(mktemp)
  cp "$file" "$backup"
  # Interrupted, the file gets its old hash back, never the placeholder.
  trap 'cp "$backup" "$file"; rm -f "$backup" "$log" "$file.tmp"; exit 130' INT
  trap 'cp "$backup" "$file"; rm -f "$backup" "$log" "$file.tmp"; exit 143' TERM
  trap 'rm -f "$backup" "$log" "$file.tmp"' EXIT
  write() {
      sed "s|\"$old\"|\"$1\"|" "$backup" > "$file.tmp" && mv "$file.tmp" "$file"
  }

  write "$fake"
  # Exit status ignored: with the placeholder the build must fail.
  nix build .#web.pnpmDeps --no-link > "$log" 2>&1 || true
  new=$(sed -n 's/^ *got: *\(sha256-[A-Za-z0-9+/=]*\)$/\1/p' "$log")
  case $new in
      sha256-*) ;;
      *)
          cp "$backup" "$file"
          echo "FAIL: the dependencies did not build; $file is unchanged:" >&2
          tail -n 20 "$log" >&2
          exit 1
          ;;
  esac
  write "$new"
  if [ "$new" = "$old" ]; then
      echo "ok: the hash was already right ($new)"
  else
      echo "ok: $old -> $new in $file"
  fi
  ```
