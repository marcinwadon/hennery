# Image attachments (plan 6a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ] `) syntax for tracking.

**Goal:** The operator can send images in a prompt, and the transcript can show them later (ACP core §7; umbrella §1.2: "Image attachments in prompts"):
- The collector checks a prompt's content before anything is written: text and image blocks only; png, jpeg, gif or webp, each image's bytes beginning like the type it claims; ≤ 5 MiB decoded each, ≤ 20 images, ≤ 16 MiB decoded together (ACP core §11).
- Images are stored once each as content-addressed files, `<data>/attachments/<sha256>`, written whole and private, and recorded in two new tables, `attachments` and `event_attachments`.
- The turn and its `user_turn` event hold references to the images, never their bytes. Only the frame to the host carries the bytes, in the blocks as checked.
- `GET /api/attachments/{sha256}` serves an image of the owner's, cache-immutable; `GET /api/settings/attachments` gives the store's size for Settings (maintainer decision 6a: no cap in v1, usage shown).
- The host announces `images`, reads frames up to ACP core §11's 32 MiB as the collector does, and refuses images to an agent whose `initialize` offers none. The collector never sends an image to a host without `images`.
- The fake ACP adapter takes images and echoes each one's hash.
- The spec amendments of this area, B2a's open `images` capability among them, are written into the ACP core spec.

The API only. The composer and the transcript's images are the frontend's (plan 4); "After this plan" records what it must do.

**Architecture:**
- **Wire** (`hennery-proto`): `StoredBlock` (a stored prompt block: text, or an image as `{mimeType, sha256, size}`) and `AttachmentUsage`; the `hello.capabilities` doc no longer says "a closed list". The schema and TypeScript files are regenerated.
- **Collector** (`hennery-sessions`):
  - `content.rs` (new): `check`, the pure check of a prompt's content, which splits what it accepts into the blocks to store, the blocks to send, and the images' bytes;
  - `attachments.rs` (new): writing and reading the files, under names that are a SHA-256 only;
  - `store.rs`: migration 8 (`attachments`, `event_attachments`), `save_images`, `open_prompt`, the links written with `user_turn`, `attachment`, `attachment_usage`;
  - `api.rs`: the prompt route checks before it writes, with a body limit of its own; the two new routes; `images_unsupported` mapped to 409.
- **Host** (`hennery-host`): `connection.rs` announces `images` and reads frames up to 32 MiB; `session.rs` keeps `promptCapabilities.image` from `initialize` and refuses images to an agent without it.
- **Tests:** the fake adapter (`hennery-testkit`) offers images (or not, `no_images`) and echoes each one's type and hash. A scripted host over real HTTP (`crates/hennery-testkit/tests/images.rs`), the real host end to end (`e2e.rs`), the store (`crates/hennery-sessions/tests/attachments.rs`, `owner.rs`), and the unit tests of the two new modules.
- **Spec:** ACP core §3.3, §4.4, §7, §8, §9 and §15 (Task 6).

**Tech Stack:** Rust (edition 2024, MSRV 1.88), rusqlite 0.40 (bundled SQLite), tokio, axum 0.8.9, tokio-tungstenite 0.29. One new crate: `base64 = "=0.22.1"`, already in `Cargo.lock` through other crates; `sha2` (`=0.10.9`) was the kernel's and is now the collector's and the testkit's too. `Cargo.lock` changes in Tasks 2 and 4, each by one `cargo build --workspace` without `--locked`; every other command runs `--locked`.

## Decisions this plan makes where the spec is silent

These were confirmed by a stronger-model security review on the maintainer's behalf (2026-10-02, "approve after amendments"). Each gives the choice, the alternatives, and the cost if it is wrong, so a reviewer can confirm it on its own. Decisions the review changed are marked "(amended after the security review of 2026-10-02)". Items marked **(amendment)** depart from explicit spec text; Task 6 writes them into the ACP core spec.

**What the review changed:**
- A1: the host is sent the blocks as checked, not as the request had them (decision 6). An image's `uri`, and any block's `annotations` or `_meta`, would otherwise reach the agent unchecked: a `uri` such as `file:///etc/passwd` gets around decision 4. And the frame's bound (decision 11) holds by construction only then, since a block carrying only checked strings is never longer than the request it came from. `check` takes the content by value, so an image's base64 moves into the frame rather than being copied.
- A2: the spec amendments are written into ACP core (Task 6), not only listed.
- Optional hardening taken:
  - O3: the attachment directory is synced after each rename (decision 7);
  - O4: client text echoed in a refusal is cut to 40 characters (decision 4);
  - O8: `Cross-Origin-Resource-Policy: same-origin` on the attachment route (decision 8).

  O1 (`Clear-Site-Data: "cache"` on logout), O2 (a concurrency limit on the prompt route), O5 (per-owner files before a second owner), O6 (agent updates still carry images verbatim) and O7 (the frontend's handling of pre-6a blocks) are recorded in "After this plan".

1. **Everything that refuses a prompt is checked before anything is written, except the host's per-agent refusal and a failed send, which abandon the turn and leave its images unreferenced (recorded).** (amended after the security review's re-confirmation, N1)
   - **Choice:** the prompt route, in this order:
     1. `content::check`, pure (decisions 4, 11);
     2. the session: 404 `not_found`, then 409 `not_attached` unless `active`;
     3. for a prompt with images: the host's readiness (409 `host_offline`), then its `images` capability (409 `images_unsupported`, decision 3), then a turn already open (409 `turn_in_progress`);
     4. the files (`save_images`, decision 7);
     5. `open_prompt`: the turn row with the stored blocks, and each image's `attachments` row, in one transaction (409 `turn_in_progress` if a turn opened meanwhile);
     6. the frame, with the blocks as checked (decision 6).
   - Readiness comes before the capability because a host that is gone has no capabilities: the other order would answer an offline host `images_unsupported`. Before this plan the route checked nothing before `open_turn`, and a text-only prompt still does not check readiness first: its `NotConnected` abandons the turn as before.
   - The early `turn_in_progress` saves writing files for a prompt `open_prompt` would refuse. It is best effort: a turn that opens between the two leaves its files behind (recorded).
   - **Alternatives:** write the files after `open_turn`, and abandon the turn when a write fails. That trades orphaned files for a turn opened and abandoned on a disk error; and a refused prompt would still have touched the database.
   - **Cost if wrong:** a reordering inside one handler.
2. **Images are refused per agent, by its host, when its `initialize` offers none.**
   - **Choice:** the host announces `images` unconditionally: it can carry image blocks. Each session keeps its agent's `promptCapabilities.image` from `initialize` (on `session/new` and `session/load` alike), and a prompt with an image block to an agent without it is refused `error{images_unsupported}` before `turn_started` (ACP: a client sends images only to an agent that offers them). The collector maps that code to 409, and its existing undo abandons the turn.
   - **What remains:** the collector stored the files before it sent the prompt, so they stay, unreferenced (recorded). The UI cannot know beforehand, per agent: that needs `hello.agents`, another plan's (recorded).
   - **Alternatives:**
     - **Send it anyway** and let the agent fail: ACP says not to, and an adapter answers `-32602`, which ends the turn `failed` after it started.
     - **Announce `images` only when every configured agent takes them:** one text-only agent would hide images for all of them.
   - **Cost if wrong:** one more condition in the actor.
3. **A host without `images` gets nothing: 409 `images_unsupported`.**
   - **Choice:** as `park_unsupported` (B2a decision): checked against the host's current connection, before anything is written; nothing is sent.
   - **A race remains:** a host that reconnects on an older build between the check and the send would be sent the images (recorded; capabilities are per connection, and the window is one handler).
   - **Cost if wrong:** a status code.
4. **Only text and image blocks; three refusals.** (amended after the security review of 2026-10-02: O4)
   - **Choice:**
     - 400 `empty_prompt`: no blocks, or no image and no text but whitespace. **(amendment)** Before this plan only an empty array was refused; a prompt of `"  "` reached the agent (P-16's class).
     - 400 `invalid_content`: a block that is not text or image (`audio`, `resource`, `resource_link`, an untyped block), an image of another type, data that is not strict standard base64, or bytes that do not begin like the type they claim (PNG, JPEG, GIF and WebP signatures).
     - 413 `content_too_large`: more than 20 images, an image over 5 MiB, or more than 16 MiB together.
     - Client text echoed in a refusal (a block's type, an image's `mimeType`) is cut to 40 characters (O4): otherwise up to 24 MiB of it could come back in the error.
   - **Why only two kinds:** ACP core §7 says "text and image blocks", and the frontend builds only those. Audio needs a capability of its own, a `resource` would need its contents stripped before storage as images are, and a `resource_link` names a file on the host.
   - A body over the route's limit gets axum's own plain-text 413, not an `ApiError` (recorded: 3c's deferred `JsonRejection` fix, once for every route).
   - **Cost if wrong:** another block kind later is one more arm in `check`.
5. **Attachments are keyed by owner and hash (amendment to ACP core §8).**
   - **Choice:** migration 8:

     ```sql
     attachments(owner_id TEXT NOT NULL REFERENCES owners(id), sha256 TEXT NOT NULL, mime TEXT NOT NULL,
       size INTEGER NOT NULL, created_at TEXT NOT NULL, PRIMARY KEY (owner_id, sha256))
     event_attachments(event_id INTEGER NOT NULL REFERENCES events(event_id), sha256 TEXT NOT NULL,
       position INTEGER NOT NULL, owner_id TEXT NOT NULL REFERENCES owners(id),
       PRIMARY KEY (event_id, position), FOREIGN KEY (owner_id, sha256) REFERENCES attachments(owner_id, sha256))
     ```

     - One `attachments` row per owner and image: another owner's copy of an image is a row of its own, and the read is owner-scoped by construction. The files on disk are shared by hash.
     - `event_attachments.position` is the block's index in the `user_turn`'s content, so a link names `content[position]` directly. One row per image block, a repeated image included.
     - The links are written with the `user_turn`, in its transaction, each guarded by `EXISTS` on the owner's `attachments` row.
     - Both tables carry `owner_id` from their first migration. The audit (`owner_filter.rs`) reads the four new statements: `store.rs`'s floor goes from 77 to 81.
   - **Alternatives:** the spec's `sha256 PK`. With a second owner, `ON CONFLICT DO NOTHING` would hide the other owner's row, and the read could not be owner-scoped by a key. A second owner needs O5 too (recorded).
   - **Cost if wrong:** a migration of two small tables.
6. **The turn and the `user_turn` event hold references; the host gets the blocks as checked.** (amended after the security review of 2026-10-02: A1)
   - **Choice:** `StoredBlock`, in `hennery-proto` and exported to TypeScript:
     - `{"type": "text", "text": …}`;
     - `{"type": "image", "mimeType": …, "sha256": …, "size": …}`, `size` decoded.

     `turns.content` holds these, and so the `user_turn` event, which copies it, and every replay of it. The host is sent `{"type": "text", "text"}` and `{"type": "image", "mimeType", "data"}`: every other field (`uri`, `annotations`, `_meta`) is dropped from both (A1).
   - **Alternatives:** keep the blocks verbatim apart from `data`. An image's `uri` could then name anything, and the timeline would show something other than what the agent received.
   - **Cost if wrong:** stored blocks are JSON; a field added later is additive.
7. **Files are written whole, private and once.** (amended after the security review of 2026-10-02: O3)
   - **Choice:** `<data>/attachments/<sha256>`, the directory beside `hennery.db` (from `Store::open`'s path), created 0700 on the first write. Each file goes to `.<sha256>.<random>.tmp` in the same directory (`create_new`, 0600), is synced, renamed over its name, and the directory synced (O3). A name that exists already is kept: it is those bytes. Names must be 64 lowercase hex digits, or the module refuses them, on write and read alike. An in-memory store keeps no files.
   - **Alternatives:** BLOBs in SQLite (the umbrella §4 rules them out: "Content-addressed files in the data directory, not BLOBs").
   - **Cost if wrong:** a crash between the write and the rename leaves a `.tmp` file (recorded: a sweep).
8. **`GET /api/attachments/{sha256}` serves an image as what it is, to its owner only.** (amended after the security review of 2026-10-02: O8)
   - **Choice:** behind the operator layers (the cookie, and `Sec-Fetch-Site` for a `GET`), owner-scoped by the `attachments` row. `Content-Type` is the stored type, one of the four; `X-Content-Type-Options: nosniff`; `Content-Security-Policy: default-src 'none'`; `Cross-Origin-Resource-Policy: same-origin` (O8); `Cache-Control: private, max-age=31536000, immutable`, since a name is a hash and its bytes never change. 404 `not_found` for a name that is not a hash, an unknown one, another owner's, or one whose file is gone (logged).
   - SVG cannot be stored, and the type is never sniffed, so no stored image runs as a document.
   - `private` keeps shared caches out. The browser's own cache keeps an image after logout on a shared device (O1, recorded).
   - **Cost if wrong:** headers.
9. **Rows written before this plan are left as they are.**
   - **Choice:** before 6a nothing refused images, so a database may hold an image's base64 in `turns.content` and its `user_turn`. No migration rewrites them; such a block names no attachment and links nothing (`content_stored_before_attachments_links_nothing`).
   - **Alternatives:** a migration that extracts them into files: code for databases that, with no frontend yet, hold none.
   - **Cost if wrong:** a one-off migration later.
10. **The store's size for Settings: `GET /api/settings/attachments` (amendment to ACP core §9).**
    - **Choice:** `AttachmentUsage {count, bytes}`, from an owner-scoped `count(*)` and `sum(size)` over `attachments`, behind the operator layers. Each image counts once, however often it was sent. It is the rows, not a walk of the directory: orphans with a row count, a leftover `.tmp` does not.
    - **Why there:** no Settings API exists; a read-only sub-resource sits beside a future `PATCH /api/settings` without conflict (the review's answer d).
    - **Cost if wrong:** a route name; the frontend has not been written against it.
11. **Limits: one body limit, and 32 MiB frames at both ends.**
    - **Choice:**
      - `DefaultBodyLimit::max(24 MiB)` on the prompt route only (`content::PROMPT_BODY_LIMIT`): 16 MiB of images is 21.4 MiB of base64, the rest is for text. Every other route keeps axum's 2 MB (`only_the_prompt_route_takes_a_large_body_and_its_limit_holds`).
      - A static assertion: the body limit plus 1 MiB fits in the 32 MiB frame (`ws::MAX_FRAME`). With A1, a frame is never longer than its body.
      - The host reads frames and messages up to 32 MiB (`connect_async_with_config`), as the collector does. Before this plan it used tungstenite's default 16 MiB frame, below a full prompt (revert-probed: 503 `delivery_unknown`).
      - `check` reads an image's size from its base64's length before decoding it.
    - **Cost if wrong:** constants.
12. **`base64` and `sha2` compiled optimised in development.**
    - **Choice:** `[profile.dev.package.base64]` and `[profile.dev.package.sha2]` at `opt-level = 3`, as `argon2` already is: the content tests decode and hash 16 MiB several times; unoptimised they take 20 s, optimised 0.6 s.
    - **Cost if wrong:** two profile entries.

## Review Focus

These are the inputs most likely to bite a real user that the obvious tests would not exercise, most likely first. Each is pinned by the named tests.

1. **A prompt at the limit, through a real host to the agent.**
   - Expected: 3 × 5 MiB and 1 MiB of PNGs with text, about 21.4 MiB of JSON, is accepted, reaches the agent whole (it echoes each image's hash), and ends `completed`.
   - Tests: Task 5 `a_prompt_at_the_limit_reaches_the_agent_whole`; Task 4 `a_prompt_at_the_limit_reaches_the_host_whole_and_is_stored_by_reference`.
2. **Images never stored or replayed as bytes.**
   - Expected: `turns.content`, the `user_turn` event and the timeline hold references; the timeline of a 16 MiB prompt stays under 64 KiB; each image is served back whole with its headers.
   - Tests: Task 3 `a_prompts_images_are_stored_once_each_and_referenced_never_carried`; Task 4's limit test.
3. **Fields the agent must not see** (the review's A1).
   - Expected: an image's `uri` and any block's `annotations` or `_meta` never reach the host.
   - Tests: Task 2 `the_host_is_sent_only_what_was_checked`; Task 4's limit test.
4. **A refused prompt leaves nothing behind.**
   - Expected: no turn, no file, nothing sent, for refused content, a host without `images`, an offline host and a prompt during a turn; a host's refusal frees the turn.
   - Tests: Task 4 `refused_content_opens_no_turn_and_writes_no_file`, `an_image_prompt_to_a_host_without_images_is_refused_before_anything_is_written`, `an_image_prompt_to_an_offline_host_is_host_offline`, `an_image_prompt_during_a_turn_writes_no_file`, `a_host_refusing_an_image_prompt_frees_the_turn`.
5. **An agent that takes no images.**
   - Expected: 409 `images_unsupported`, and text still goes.
   - Tests: Task 5 `an_agent_that_takes_no_images_is_never_sent_one`.
6. **Images that are not what they claim, and the limits exactly.**
   - Expected: a JPEG or an SVG sent as a PNG is refused; exactly 5 MiB, 20 images and 16 MiB pass, one more byte or image does not.

//! Prompt content (ACP core §7, plan 6a): what the collector accepts in a
//! prompt, and what it stores of it.
//!
//! A prompt is ACP ContentBlocks, text and images, in order. `check` reads
//! it before anything is written: it refuses another block type, an image
//! of another type or whose bytes are not what it claims, and the limits of
//! ACP core §11. What it accepts it splits into the blocks to store, where
//! an image is the attachment it becomes (`StoredBlock`), the blocks the
//! host is sent, which keep only what was checked, and the images' bytes,
//! for the attachment files.

#[cfg(test)]
mod tests {
    use super::*;
    use serde_json::json;

    /// `len` bytes that begin like a `mime` image.
    fn bytes(mime: &str, len: usize) -> Vec<u8> {
        let head: &[u8] = match mime {
            "image/png" => b"\x89PNG\r\n\x1a\n",
            "image/jpeg" => &[0xff, 0xd8, 0xff, 0xe0],
            "image/gif" => b"GIF89a",
            "image/webp" => b"RIFF\0\0\0\0WEBP",
            _ => b"",
        };
        let mut out = head.to_vec();
        out.resize(len.max(head.len()), 7);
        out
    }

    fn image_block(mime: &str, data: &[u8]) -> Value {
        json!({ "type": "image", "mimeType": mime, "data": STANDARD.encode(data) })
    }

    fn refusal(content: Value) -> Refusal {
        check(content.as_array().unwrap().clone()).unwrap_err()
    }

    #[test]
    fn text_and_images_are_stored_in_order_with_the_images_as_attachments() {
        let png = bytes("image/png", 100);
        let checked = check(vec![
            json!({ "type": "text", "text": "look at" }),
            image_block("image/png", &png),
            json!({ "type": "text", "text": "and" }),
            image_block("image/png", &png),
        ])
        .unwrap();
        let sha = hex::encode(Sha256::digest(&png));
        let image = StoredBlock::Image {
            mime_type: "image/png".into(),
            sha256: sha.clone(),
            size: 100,
        };
        assert_eq!(
            checked.stored,
            vec![
                StoredBlock::Text { text: "look at".into() },
                image.clone(),
                StoredBlock::Text { text: "and".into() },
                image,
            ]
        );
        assert_eq!(checked.images.len(), 2);
        assert_eq!(
            (checked.images[0].sha256.as_str(), checked.images[0].bytes.as_slice()),
            (sha.as_str(), &png[..])
        );
        // What is stored never carries the bytes.
        let stored = serde_json::to_string(&checked.stored_json()).unwrap();
        assert!(
            !stored.contains("data") && !stored.contains(&STANDARD.encode(&png)),
            "{stored}"
        );
    }

        assert!(check(vec![image_block("image/png", &bytes("image/png", MAX_IMAGE_BYTES))]).is_ok());

            "image/png",
            &bytes("image/png", MAX_IMAGE_BYTES + 1)

/// Why a prompt is refused (ACP core §9).
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Refusal {
    /// No image, and no text but whitespace: 400 `empty_prompt`.
    Empty,
    /// A block the collector does not accept: 400 `invalid_content`.
    Invalid(String),
    /// Over one of the limits: 413 `content_too_large`.
    TooLarge(String),
}

/// Check a prompt's content, and split what it accepts into the blocks to
/// store, the blocks to send and the images' bytes. Takes the content, so
/// an image's base64 moves into what is sent rather than being copied.
pub fn check(content: Vec<Value>) -> Result<Checked, Refusal> {
    let mut stored = Vec::with_capacity(content.len());
    let mut sent = Vec::with_capacity(content.len());
    let mut images = Vec::new();
    let mut total = 0usize;
    let mut said_something = false;
    for (n, block) in content.into_iter().enumerate() {
        let Value::Object(mut block) = block else {
            return Err(Refusal::Invalid(format!("block {n}: a content block needs a type")));
        };
        let kind = block.get("type").and_then(Value::as_str).map(str::to_owned);
        match kind.as_deref() {
            Some("text") => {
                let Some(Value::String(text)) = block.remove("text") else {
                    return Err(Refusal::Invalid(format!("block {n}: a text block needs its text")));
                };
                said_something |= !text.trim().is_empty();
                stored.push(StoredBlock::Text { text: text.clone() });
                sent.push(json!({ "type": "text", "text": text }));
            }
            Some("image") => {
                if images.len() == MAX_IMAGES {
                    return Err(Refusal::TooLarge(format!("a prompt takes at most {MAX_IMAGES} images")));
                }
                let (image, data) = image(n, &mut block, MAX_IMAGES_TOTAL - total)?;
                total += image.bytes.len();
                stored.push(StoredBlock::Image {
                    mime_type: image.mime.clone(),
                    sha256: image.sha256.clone(),
                    size: image.bytes.len() as u64,
                });
                sent.push(json!({ "type": "image", "mimeType": image.mime, "data": data }));
                images.push(image);
            }
            Some(other) => {
                return Err(Refusal::Invalid(format!(
                    "block {n}: {} blocks are not accepted; a prompt is text and images",
                    shown(other)
                )));
            }
            None => return Err(Refusal::Invalid(format!("block {n}: a content block needs a type"))),
        }
    }
    if !said_something && images.is_empty() {
        return Err(Refusal::Empty);
    }
    Ok(Checked { stored, sent, images })
}

/// Client text echoed in a refusal (the review's O4): at most 40
/// characters of it, quoted.
fn shown(text: &str) -> String {
    let mut cut: String = text.chars().take(40).collect();
    if cut.len() < text.len() {
        cut.push('…');
    }
    format!("{cut:?}")
}

/// Decode and check block `n`, an image, with `room` bytes left of the
/// prompt's total: the image, and its base64 as it came. The size is
/// checked from the base64's length before it is decoded, so an oversized
/// image costs no decoding.
fn image(n: usize, block: &mut Map<String, Value>, room: usize) -> Result<(Image, String), Refusal> {
    let Some(Value::String(mime)) = block.remove("mimeType") else {
        return Err(Refusal::Invalid(format!("block {n}: an image needs its mimeType")));
    };
    if !IMAGE_TYPES.contains(&mime.as_str()) {
        return Err(Refusal::Invalid(format!(
            "block {n}: images must be PNG, JPEG, GIF or WebP, not {}",
            shown(&mime)
        )));
    }
    let Some(Value::String(data)) = block.remove("data") else {
        return Err(Refusal::Invalid(format!("block {n}: an image needs its data, base64")));
    };
    // Base64 is 4 characters for every 3 bytes; padding only shortens it.
    let at_least = (data.len() / 4 * 3).saturating_sub(2);
    if at_least > MAX_IMAGE_BYTES {
        return Err(too_large_image(n));
    }
    if at_least > room {
        return Err(too_large_total());
    }
    let bytes = STANDARD
        .decode(&data)
        .map_err(|_| Refusal::Invalid(format!("block {n}: the image's data is not base64")))?;
    if bytes.len() > MAX_IMAGE_BYTES {
        return Err(too_large_image(n));
    }
    if bytes.len() > room {
        return Err(too_large_total());
    }
    if sniff(&bytes) != Some(mime.as_str()) {
        return Err(Refusal::Invalid(format!(
            "block {n}: the image is not the {mime} it says it is"
        )));
    }
    let image = Image {
        sha256: hex::encode(Sha256::digest(&bytes)),
        mime,
        bytes,
    };
    Ok((image, data))
}

fn too_large_image(n: usize) -> Refusal {
    Refusal::TooLarge(format!("block {n}: an image takes at most 5 MiB"))
}

fn too_large_total() -> Refusal {
    Refusal::TooLarge("a prompt's images take at most 16 MiB together".to_string())
}

/// The image type `bytes` begin like, by their signature.
pub fn sniff(bytes: &[u8]) -> Option<&'static str> {
    if bytes.starts_with(b"\x89PNG\r\n\x1a\n") {
        Some("image/png")
    } else if bytes.starts_with(&[0xff, 0xd8, 0xff]) {
        Some("image/jpeg")
    } else if bytes.starts_with(b"GIF87a") || bytes.starts_with(b"GIF89a") {
        Some("image/gif")
    } else if bytes.len() >= 12 && bytes.starts_with(b"RIFF") && &bytes[8..12] == b"WEBP" {
        Some("image/webp")
    } else {
        None
    }
}

/// `name` is a SHA-256 in lowercase hex: the only names this module reads
/// or writes, so a name from a URL can never leave the directory.
pub fn is_sha256(name: &str) -> bool {
    name.len() == 64 && name.bytes().all(|b| b.is_ascii_digit() || (b'a'..=b'f').contains(&b))
}

fn path(dir: &Path, sha256: &str) -> std::io::Result<PathBuf> {
    if !is_sha256(sha256) {
        return Err(std::io::Error::new(
            std::io::ErrorKind::InvalidInput,
            "an attachment is named by its SHA-256",
        ));

/// Store `bytes` as `sha256` in `dir`, creating `dir` (0700) if it does
/// not exist yet. A file of that name is already those bytes, so it is
/// kept as it is.
pub fn write(dir: &Path, sha256: &str, bytes: &[u8]) -> std::io::Result<()> {
    let target = path(dir, sha256)?;
    match std::fs::DirBuilder::new().mode(0o700).create(dir) {
        Ok(()) => {}
        Err(err) if err.kind() == std::io::ErrorKind::AlreadyExists => {}
        Err(err) => return Err(err),
    }
    if target.exists() {
        return Ok(());
    }
    let temp = dir.join(format!(
        ".{sha256}.{}.tmp",
        hex::encode(hennery_kernel::secret::random_bytes::<8>())
    ));
    let written = (|| {
        let mut file = std::fs::OpenOptions::new()
            .write(true)
            .create_new(true)
            .mode(0o600)
            .open(&temp)?;
        file.write_all(bytes)?;
        file.sync_all()?;
        std::fs::rename(&temp, &target)?;
        // The rename is durable only once the directory is (the review's
        // O3): else a power loss could leave a recorded image without its
        // file.
        std::fs::File::open(dir)?.sync_all()
    })();
    if written.is_err() {
        let _ = std::fs::remove_file(&temp);
    }
    written
}

        Ok(bytes) => Ok(Some(bytes)),
        Err(err) if err.kind() == std::io::ErrorKind::NotFound => Ok(None),
        Err(err) => Err(err),

type Ws = tokio_tungstenite::WebSocketStream<tokio_tungstenite::MaybeTlsStream<tokio::net::TcpStream>>;

/// The test playing a host. It reads frames as large as ACP core §11's
/// 32 MiB, as the hennery host does.
struct ScriptedHost {
    ws: Ws,
    seq: u64,
}

impl ScriptedHost {
    async fn connect(collector: &Collector, capabilities: Capabilities) -> Self {
        let config = WebSocketConfig::default()
            .max_message_size(Some(32 << 20))
            .max_frame_size(Some(32 << 20));
        let (ws, response) = tokio_tungstenite::connect_async_with_config(
            format!("ws://{}/api/hosts/ws", collector.addr),
            Some(config),
            false,
        )
        .await
        .unwrap();
        let nonce = hex::decode(response.headers()[HELLO_NONCE_HEADER].to_str().unwrap()).unwrap();
        let mut host = Self { ws, seq: 0 };
        host.send(&HostFrame::Hello {
            protocol_version: PROTOCOL_VERSION.into(),
            host_version: "test".into(),
            host_id: HOST.into(),
            proof: host_key().sign_hello(&nonce, HOST, PROTOCOL_VERSION),
            capabilities,
            attached_sessions: vec![],
        })
        .await;
        assert!(matches!(host.next().await, CollectorFrame::HelloAck { .. }));
        host.send(&HostFrame::ResendComplete).await;
        let deadline = tokio::time::Instant::now() + Duration::from_secs(10);
        while !collector.state.hub.is_ready(HOST) {
            assert!(tokio::time::Instant::now() < deadline, "host never ready");
            tokio::time::sleep(Duration::from_millis(20)).await;
        }
        host
    }

    async fn send(&mut self, frame: &HostFrame) {
        self.ws
            .send(Message::text(serde_json::to_string(frame).unwrap()))
            .await
            .unwrap();
    }

    async fn emit(&mut self, session_id: &str, body: SessionBody) {
        self.seq += 1;
        let frame = HostFrame::Session {
            session_id: session_id.into(),
            seq: self.seq,
            body,
        };
        self.send(&frame).await;
    }

    /// The next collector frame that is not an `ack`.
    async fn next(&mut self) -> CollectorFrame {
        tokio::time::timeout(Duration::from_secs(20), async {
            loop {
                match self.ws.next().await {
                    Some(Ok(Message::Text(text))) => match serde_json::from_str(&text).unwrap() {
                        CollectorFrame::Ack { .. } => {}
                        frame => return frame,
                    },
                    Some(Ok(_)) => {}
                    other => panic!("collector connection ended: {other:?}"),
                }
            }
        })
        .await
        .expect("a collector frame within 20s")
    }

    /// Nothing but acks arrives for a while.
    async fn nothing_more(&mut self) {
        let more = tokio::time::timeout(Duration::from_millis(300), self.next()).await;
        assert!(more.is_err(), "the host was sent {more:?}");
    }
}

/// `len` bytes of a PNG, different for each `seed`.
fn png(seed: u8, len: usize) -> Vec<u8> {
    let mut bytes = b"\x89PNG\r\n\x1a\n".to_vec();
    bytes.extend((0..len - 8).map(|i| seed.wrapping_mul(31).wrapping_add((i % 251) as u8)));
    bytes
}

fn image(mime: &str, bytes: &[u8]) -> Value {
    json!({ "type": "image", "mimeType": mime, "data": STANDARD.encode(bytes) })
}

fn sha(bytes: &[u8]) -> String {
    hex::encode(Sha256::digest(bytes))
}

/// Answer the prompt the collector sends with `turn_started`, and return
/// its content.
async fn accept_prompt(host: &mut ScriptedHost, session: &str) -> Vec<Value> {
    let CollectorFrame::Prompt {
        request_id,
        turn_id,
        content,
        ..
    } = host.next().await
    else {
        panic!("expected a prompt");
    };
    host.emit(session, SessionBody::TurnStarted { request_id, turn_id })
        .await;
    content
}

/// The most a prompt may carry (ACP core §11): 3 × 5 MiB and 1 MiB of
/// images, 16 MiB together, about 21.4 MiB of base64 and so one frame
/// larger than tungstenite's default 16 MiB, with text around them. The
/// host is sent what was checked and nothing else (the review's A1: no
/// `uri`, `annotations` or `_meta`); the timeline and the turn hold
/// references; each image is served back whole.
#[tokio::test]
async fn a_prompt_at_the_limit_reaches_the_host_whole_and_is_stored_by_reference() {
    let collector = Collector::start().await;
    let mut host = ScriptedHost::connect(&collector, Capabilities(vec![Capability::Park, Capability::Images])).await;
    let session = started_session(&collector, &mut host).await;
    let images: Vec<Vec<u8>> = [5 << 20, 5 << 20, 5 << 20, 1 << 20]
        .iter()
        .enumerate()
        .map(|(n, len)| png(n as u8 + 1, *len))
        .collect();
    let mut checked = vec![json!({ "type": "text", "text": "compare these" })];
    checked.extend(images.iter().map(|bytes| image("image/png", bytes)));
    // What the client sends: the same, with fields the agent never sees.
    let mut content = checked.clone();
    content[0]["_meta"] = json!({ "x": 1 });
    content[0]["annotations"] = json!({ "priority": 1 });
    content[1]["uri"] = json!("file:///etc/passwd");
    let body = json!({ "content": content });
    assert!(serde_json::to_vec(&body).unwrap().len() > 21 << 20);

    let c = client(&collector);
    let c2 = c.clone();
    let url = prompt_url(&collector, &session);
    let call = tokio::spawn(async move { post(&c2, url, &body).await });
    let sent = accept_prompt(&mut host, &session).await;
    assert!(sent == checked, "the host is sent only what was checked");
    let (status, answer) = call.await.unwrap();
    assert_eq!(status, 202, "{answer}");

    // The timeline holds references, and no image's bytes.
    let events: Vec<EventDto> = c
        .get(collector.url(&format!("/api/sessions/{session}/events")))
        .send()
        .await
        .unwrap()
        .json()
        .await
        .unwrap();
    let user_turn = events.iter().find(|e| e.kind == "user_turn").expect("user_turn");
    let stored = &user_turn.body["content"];
    assert_eq!(stored[0], json!({ "type": "text", "text": "compare these" }));
    for (n, bytes) in images.iter().enumerate() {
        assert_eq!(
            stored[n + 1],
            json!({ "type": "image", "mimeType": "image/png", "sha256": sha(bytes), "size": bytes.len() })
        );
    }
    assert!(serde_json::to_vec(&events).unwrap().len() < 64 << 10);

    // Each image is served back, whole, as what it is.
    for bytes in &images {
        let resp = c
            .get(collector.url(&format!("/api/attachments/{}", sha(bytes))))
            .send()
            .await
            .unwrap();
        assert_eq!(resp.status(), 200);
        let headers = resp.headers().clone();
        assert_eq!(headers["content-type"], "image/png");
        assert_eq!(headers["x-content-type-options"], "nosniff");
        assert_eq!(headers["content-security-policy"], "default-src 'none'");
        assert_eq!(headers["cache-control"], "private, max-age=31536000, immutable");
        assert_eq!(headers["cross-origin-resource-policy"], "same-origin");
        assert_eq!(resp.bytes().await.unwrap().as_ref(), &bytes[..]);
    }
    let usage: AttachmentUsage = c
        .get(collector.url("/api/settings/attachments"))
        .send()
        .await
        .unwrap()
        .json()
        .await
        .unwrap();
    assert_eq!(
        usage,
        AttachmentUsage {
            count: 4,
            bytes: 16 << 20
        }
    );
}

/// One of the owner's images (plan 6a), by its hash. Served as the type it
/// was stored as, never sniffed, and never as a document: no script, no
/// style, no frame. Its name is its hash, so it never changes: cached for a
/// year, privately, since it needs the cookie.
async fn attachment(State(state): State<AppState>, Path(sha256): Path<String>) -> Response {
    let found = match state.store.attachment(&sha256) {
        Ok(Some(found)) => found,
        Ok(None) => return error(StatusCode::NOT_FOUND, "not_found", "no such attachment"),
        Err(err) => return internal(err),
    };
    let Ok(mime) = HeaderValue::from_str(&found.mime) else {
        return internal(anyhow::anyhow!("attachment {sha256} has a type no header can carry"));
    };
    let headers = [
        (header::CONTENT_TYPE, mime),
        (header::X_CONTENT_TYPE_OPTIONS, HeaderValue::from_static("nosniff")),
        (
            header::CONTENT_SECURITY_POLICY,
            HeaderValue::from_static("default-src 'none'"),
        ),
        (
            header::CACHE_CONTROL,
            HeaderValue::from_static("private, max-age=31536000, immutable"),
        ),
        // The review's O8: no other site may embed it.
        (
            HeaderName::from_static("cross-origin-resource-policy"),
            HeaderValue::from_static("same-origin"),
        ),
    ];
    (headers, found.bytes).into_response()
}

/// `len` bytes of a PNG, different for each `seed`.
fn png(seed: u8, len: usize) -> Vec<u8> {
    let mut bytes = b"\x89PNG\r\n\x1a\n".to_vec();
    bytes.extend((0..len - 8).map(|i| seed.wrapping_mul(31).wrapping_add((i % 251) as u8)));
    bytes
}

fn image(bytes: &[u8]) -> Value {
    use base64::Engine;
    json!({ "type": "image", "mimeType": "image/png", "data": base64::engine::general_purpose::STANDARD.encode(bytes) })
}

fn sha(bytes: &[u8]) -> String {
    use sha2::Digest;
    hex::encode(sha2::Sha256::digest(bytes))
}
