# Hat logos, server side (plan 4d-B2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ] `) syntax for tracking.

**Goal:** A hat can carry a logo (kernel spec §5.1; umbrella §8.1: a hat is `{id, name, theme (colour, logo)}`), and the logo URL is safe to open directly:
- The owner uploads a **PNG** (≤ 64 KiB) as base64 in JSON. The kernel decodes it, bounded by the header before anything is allocated, and writes it afresh: `IHDR`, `IDAT`, `IEND` and nothing else. No metadata, text, profile, animation, private chunk or trailing document of the upload survives.
- `GET /api/hats/{id}/logo` serves it behind the cookie and the browser rules, as `image/png`, with `nosniff`, a sandbox policy, a fixed `Content-Disposition`, `same-origin` CORP, `private, no-cache` and a strong `ETag`; `HatItem.logo` carries that `ETag`.
- `PUT` and `DELETE /api/hats/{id}/logo` need step-up. A hat frozen for its purge takes no new logo (409 `hat_purging`) but can lose its own, and the purge takes the logo with the hat's row.
- **SVG is not taken** (nor WebP): the security review's ruling, written back into kernel §5.1 and the frontend spec's hats bullet. The web UI (plan 4d-iii) rasterises an SVG, WebP or JPEG to a PNG in the browser before it uploads.
- The server side only. The settings screen's logo row is plan 4d-iii's; "After this plan" says what it must do.

**Architecture:**
- **Kernel** (`hennery-kernel`):
  - `logo.rs` (new): the pure `from_upload`/`reencode` and their `Refusal`s (Task 1); `Hosts::hat_logo`, `set_hat_logo`, `clear_hat_logo` (Task 2). It joins the owner audit's `SOURCES`.
  - `schema.rs`: the next kernel migration, three `ADD COLUMN`s on `hats` with their checks (Task 2).
  - `hats.rs`: `HatRecord.logo` (the `ETag`), read by `hats_of` without the bytes; `hat_in` (Task 2).
  - `csp.rs`: `LOGO_POLICY` (Task 3).
- **Sessions** (`hennery-sessions`), `hats.rs`: the three routes on `/api/hats/{id}/logo`, step-up layered on `put` and `delete` alone, a 96 KiB body limit on `put` (Task 3).
- **Wire** (`hennery-proto`): `HatItem.logo?`, `SetHatLogoRequest {data}`; the schema and TypeScript files regenerated (Task 3).
- **Specs:** kernel §1.1, §3.4, §5.1, §8, §11 and the frontend spec's hats bullet (Task 4).

## Decisions this plan makes where the spec is silent

1. **PNG only; SVG and WebP are refused (the review's ruling B, narrowed by its A1).** The parent offered (A) SVG kept, with a sanitiser and a sandbox, or (B) PNG and WebP, re-encoded. The review took (B) and dropped WebP as well:
   - SVG is a document format: served from this origin it runs script the moment its URL is opened as a page, and the defence would be a sanitiser hennery owns forever. Rust has no maintained SVG sanitiser; `usvg`/`resvg` re-serialise or rasterise, but bring their own `<use>` expansion and filter CPU bombs within 64 KiB.
   - `image-webp` 0.2.4 does not bound memory by the header: in a `VP8X` file holding a `VP8` chunk, `Vp8Decoder::decode_frame` sizes its planes from the inner header (up to 16383², about 400 MB) and checks them against the canvas only after decoding; `set_memory_limit` covers only the ICC/EXIF/XMP reads. The kernel spec never asked for WebP.
   - `png` 0.18.1's `read_info` allocates at most about 128 KiB before the image data; the header can be read alone first (`read_header_info`).
   - Not a product question, the review judged: the operator can still pick an SVG, WebP or JPEG file; the browser draws it on a canvas and uploads a PNG. Only what the server stores and serves narrows. The PR flags it so the maintainer can veto it.
2. **The bounds.** At most 64 KiB decoded (kernel §5.1); the base64 string's length is checked before it is decoded (O2: over `4 × ⌈65536 / 3⌉` = 87,384 characters is `TooLarge` at once). Each side 1 to 1024 pixels, checked from `IHDR` read alone, before any ancillary chunk is parsed or any buffer sized (A2). At most 256 KiB once re-encoded (a small upload can decode to pixels that compress worse); the cap is a parameter of `reencode`, so a test reaches it (A4). The `png` decoder also gets `Limits { bytes: 4 MiB }` for its own row buffers; the frame is the caller's and is bounded by the 1024 check.
3. **The re-encoding.** `normalize_to_color8` (palettes and `tRNS` expanded, 16-bit samples cut to 8, low bit depths widened); text and `iCCP` chunks not even parsed; the first frame (an APNG's default image), sized by what `next_frame` reports (A3); written by `png::Encoder` in the colour type decoded, 8-bit, with nothing but `IHDR`, `IDAT` and `IEND`. The `ETag` is the first 128 bits of the result's SHA-256, in hex.
4. **The wire.**
   - `PUT /api/hats/{id}/logo`, `application/json` (kernel §3.3), `{"data": "<base64>"}` with `deny_unknown_fields`: strict standard base64, padded, nothing around it (no whitespace, no `data:` prefix, no URL-safe alphabet). Step-up. The body is at most 96 KiB (`DefaultBodyLimit` on `put` alone), so a larger one is 413 `body_too_large` before any parse, chunked or not (O4). An unknown hat is 404 before the upload is decoded. 200 `HatItem`.
   - Refusals, each a fixed `ApiError` (A8): 400 `invalid_logo` (not base64; not a readable PNG; a side over 1024), 413 `logo_too_large`, 415 `unsupported_logo` (not a PNG by its signature), 409 `hat_purging`. Logged at `debug` as the refusal's kind only.
   - `DELETE /api/hats/{id}/logo`: step-up; 200 `HatItem`, also when there was no logo; 404.
   - `GET /api/hats/{id}/logo`: 200 or 404 `not_found` (no hat, or no logo); the query string is ignored.
5. **The headers (A9; the parent's addition).** On the 200 and the 304: `X-Content-Type-Options: nosniff`; `Content-Security-Policy: default-src 'none'; sandbox; frame-ancestors 'none'` (no `style-src`: nothing styled is served; `csp::on_html` only touches `text/html`, so it never replaces it); `Content-Disposition: inline; filename="logo.png"`, never the hat's name; `Cross-Origin-Resource-Policy: same-origin`, as attachments have; `Cache-Control: private, no-cache`; `ETag: "<etag>"`. On the 200, `Content-Type: image/png`, chosen by a `match` on the kind stored, never the stored string. `Sec-Fetch-Dest` is not checked (O5 left): the sandbox makes a document-load harmless.
6. **Caching.** `private, no-cache` with a strong `ETag`, revalidated every time; `If-None-Match` naming it (in a list, weakly as `W/"…"`, or `*`) is a 304 with no body (RFC 9110's weak comparison). The review rejected `immutable` plus `?v=`: a second cache model to save one 304. `HatItem.logo` is the `ETag` without its quotes, absent with no logo; a client may add `?v=<logo>`, which the server ignores.
7. **The store.** The next kernel migration (`ADD COLUMN` only, 5a; the 11th on `ecc50cd`, renumbered at merge if another lane takes it first): `logo_mime TEXT CHECK (NULL or 'image/png')`, `logo_bytes BLOB CHECK (NULL or a blob)`, `logo_etag TEXT` with the check that the three are set together, on the last column, once all exist. `hats_of` reads the `ETag` only, never the bytes (it runs for every hat read). `set_hat_logo` is one `UPDATE … AND NOT EXISTS (purged_hats …)` and then classifies a miss as `Purging` or `NotFound` from the hat read in the same transaction. Both reuse `HatChange`, so the route answers through `hat_changed`. The migration's own test finds the migration by what it does (`MIGRATIONS.iter().position(|m| m.contains("ADD COLUMN logo_mime"))`), never by its index, so a renumbering changes no test code.
8. **A frozen hat (A6).** `PUT` is 409 `hat_purging`: a new logo is a new identity cue for a hat on its way out. `DELETE` succeeds: removing client data is the purge's own direction, and 9c's A12 already lets a frozen hat's name and colour change. The brief said "a frozen hat refuses changes with 409"; the review's A6 overrides it for `DELETE`, recorded here. The logo is still served while the hat is frozen (it is still listed, 9c A12).
9. **Step-up (A5).** On `put` and `delete` only, by `Handler::layer`, as the path rules and the purge do. Not `route_layer`: that would put step-up on `GET`, every `<img>`. Changing a hat's identity cues is stepped up as `PATCH /api/hats/{id}` is (5a decision 7).
10. **Off the async workers (O1).** The decode runs under `spawn_blocking`.
11. **The purge (A7).** Nothing new: `finish_purge` deletes the row and the logo with it; `secure_delete` is on for every kernel connection (`db::configure`), and the purge checkpoints the WAL. A test shows neither the logo nor the one it replaced is left in `hennery.db` or its WAL.
12. **No event.** A hat's change publishes nothing today: on `ecc50cd`, `git grep -n publish -- crates/hennery-sessions/src/hats.rs crates/hennery-kernel/src/hats.rs` finds only the purge's session deletes, and no stream carries hats (`hennery-view` names none). A logo change follows `PATCH /api/hats/{id}`: the answer is the `HatItem`, and other tabs see it at their next `GET /api/hats`. The side effect a client reads is `HatItem.logo`, the `ETag`, which changes with every new logo; each line that writes or reads it is probed.

## Review Focus

- **A PNG that is also something else.** A document after `IEND`, scripts in text chunks, a private chunk: the output must be ours alone. Task 1's metadata test.
- **A header that lies.** `IHDR` claiming 2³¹ pixels with nothing after it must be refused as `Dimensions`, from the header alone, never by trying. Task 1.
- **The URL opened as a page.** `Sec-Fetch-Site: none` or no such header, `Sec-Fetch-Dest: document`: the sandbox and the fixed type must be there. Task 3.
- **A stale step-up on `GET`.** The `<img>` must load with a session past its five minutes. Task 3 (`step_up.rs`).
- **The same field twice, or spelt `\u0064ata`.** One verdict for both spellings; duplicates refused. Task 3.
- **No event on a logo change** (Decision 12): hats have no stream; if that is wrong, a rename is wrong the same way.

  ```rust
  #[cfg(test)]
  mod tests {
      use super::*;
      use png::{BitDepth, ColorType};

      /// PNG's CRC-32 (ISO 3309), bit by bit: test fixtures only.
      fn crc32(bytes: &[u8]) -> u32 {
          let mut crc = !0u32;
          for &byte in bytes {
              crc ^= u32::from(byte);
              for _ in 0..8 {
                  crc = if crc & 1 == 1 {
                      (crc >> 1) ^ 0xedb8_8320
                  } else {
                      crc >> 1
                  };
              }
          }
          !crc
      }

      fn chunk(kind: &[u8; 4], data: &[u8]) -> Vec<u8> {
          let mut out = (data.len() as u32).to_be_bytes().to_vec();
          out.extend_from_slice(kind);
          out.extend_from_slice(data);
          let mut crc = kind.to_vec();
          crc.extend_from_slice(data);
          out.extend_from_slice(&crc32(&crc).to_be_bytes());
          out
      }

      /// `data` as a zlib stream of stored (uncompressed) blocks.
      fn zlib_stored(data: &[u8]) -> Vec<u8> {
          let mut out = vec![0x78, 0x01];
          let blocks: Vec<&[u8]> = if data.is_empty() {
              vec![&[]]
          } else {
              data.chunks(65535).collect()
          };
          for (n, block) in blocks.iter().enumerate() {
              out.push(u8::from(n + 1 == blocks.len()));
              let len = block.len() as u16;
              out.extend_from_slice(&len.to_le_bytes());
              out.extend_from_slice(&(!len).to_le_bytes());
              out.extend_from_slice(block);
          }
          let (mut a, mut b) = (1u32, 0u32);
          for &byte in data {
              a = (a + u32::from(byte)) % 65521;
              b = (b + a) % 65521;
          }
          out.extend_from_slice(&((b << 16) | a).to_be_bytes());
          out
      }

      fn ihdr(width: u32, height: u32, depth: u8, colour: u8, interlace: u8) -> Vec<u8> {
          let mut data = width.to_be_bytes().to_vec();
          data.extend_from_slice(&height.to_be_bytes());
          data.extend_from_slice(&[depth, colour, 0, 0, interlace]);
          chunk(b"IHDR", &data)
      }

      fn file(chunks: &[Vec<u8>]) -> Vec<u8> {
          let mut out = SIGNATURE.to_vec();
          for chunk in chunks {
              out.extend_from_slice(chunk);
          }
          out
      }

      /// A PNG of `pixels` as the `png` crate writes it.
      fn encode(width: u32, height: u32, colour: ColorType, depth: BitDepth, pixels: &[u8]) -> Vec<u8> {
          let mut out = Vec::new();
          let mut encoder = png::Encoder::new(&mut out, width, height);
          encoder.set_color(colour);
          encoder.set_depth(depth);
          let mut writer = encoder.write_header().unwrap();
          writer.write_image_data(pixels).unwrap();
          writer.finish().unwrap();
          out
      }

      /// The chunks of `png`, in order, by type; and the bytes after `IEND`.
      fn chunks_of(png: &[u8]) -> (Vec<String>, usize) {
          assert!(png.starts_with(SIGNATURE));
          let mut at = SIGNATURE.len();
          let mut kinds = Vec::new();
          while at + 8 <= png.len() {
              let len = u32::from_be_bytes(png[at..at + 4].try_into().unwrap()) as usize;
              let kind = String::from_utf8_lossy(&png[at + 4..at + 8]).into_owned();

              kinds.push(kind);
              if end {
                  break;
              }
          }

      }

      /// `png` decoded as the browser would see it: 8-bit, palettes expanded.
      fn pixels(png: &[u8]) -> (u32, u32, ColorType, Vec<u8>) {
          let mut decoder = png::Decoder::new(Cursor::new(png));
          decoder.set_transformations(png::Transformations::normalize_to_color8());
          let mut reader = decoder.read_info().unwrap();
          let mut buf = vec![0; reader.output_buffer_size().unwrap()];
          let frame = reader.next_frame(&mut buf).unwrap();
          buf.truncate(frame.buffer_size());
          (frame.width, frame.height, frame.color_type, buf)
      }

          let logo = reencode(input, MAX_STORED).unwrap();

          logo

      /// The chunks of a clean `png`, with `before` inserted before its first
      /// `IDAT`, `after` before its `IEND`, and `trailing` after `IEND`.
      fn with_extras(png: &[u8], before: &[Vec<u8>], after: &[Vec<u8>], trailing: &[u8]) -> Vec<u8> {
          let mut at = SIGNATURE.len();
          let mut out = SIGNATURE.to_vec();
          let mut seen_idat = false;
          while at < png.len() {
              let len = u32::from_be_bytes(png[at..at + 4].try_into().unwrap()) as usize;
              let kind = &png[at + 4..at + 8];
              if kind == b"IDAT" && !seen_idat {
                  seen_idat = true;
                  before.iter().for_each(|c| out.extend_from_slice(c));
              }
              if kind == b"IEND" {
                  after.iter().for_each(|c| out.extend_from_slice(c));
              }
              out.extend_from_slice(&png[at..at + 12 + len]);
              at += 12 + len;
          }
          out.extend_from_slice(trailing);
          out
      }
  ```

  ```rust
  //! Hat logos (kernel spec §5.1; plan 4d-B2). A logo is uploaded as a PNG,
  //! at most 64 KiB, and stored and served only as this module re-encodes it:
  //! decoded to plain 8-bit pixels, then written afresh as `IHDR`, `IDAT` and
  //! `IEND`, so no text, metadata, profile, animation or trailing bytes of the
  //! upload survive (the security review's ruling B: no SVG, no WebP). The
  //! browser turns any other format into a PNG before it uploads.
  //!
  //! Memory is bounded before anything is allocated by the image's size: the
  //! header alone is read first, and an image over `MAX_SIDE` pixels either way
  //! is refused there (the review's A2).

  use base64::Engine;
  use sha2::{Digest, Sha256};
  use std::io::Cursor;

  /// The largest upload, decoded (kernel spec §5.1).
  pub const MAX_UPLOAD: usize = 64 * 1024;

  /// The widest and tallest logo, in pixels.
  pub const MAX_SIDE: u32 = 1024;

  /// The largest logo stored, once re-encoded: a small upload can decode to
  /// pixels that compress worse than it did.
  pub const MAX_STORED: usize = 256 * 1024;

  /// The one kind a logo is stored and served as.
  pub const MIME_PNG: &str = "image/png";

  const SIGNATURE: &[u8] = b"\x89PNG\r\n\x1a\n";

  /// What the decoder may allocate besides the frame: its row buffers. The
  /// frame itself is bounded by `MAX_SIDE`, checked from the header first.
  const DECODER_LIMIT: usize = 4 << 20;

  /// A logo as it is stored: always a PNG of ours.
  #[derive(Debug, Clone, PartialEq, Eq)]
  pub struct Logo {
      pub bytes: Vec<u8>,
      /// What `GET /api/hats/{id}/logo` answers as its `ETag` (without the
      /// quotes): the first 128 bits of the bytes' SHA-256, in hex.
      pub etag: String,
  }

  /// Why an upload is not a logo. Each has its own status and fixed message
  /// at the route; none carries the decoder's words or the upload's bytes
  /// (the review's A8).
  #[derive(Debug, Clone, Copy, PartialEq, Eq)]
  pub enum Refusal {
      /// Not strict standard base64 (padded, no whitespace, no `data:`).
      NotBase64,
      /// Over `MAX_UPLOAD` decoded, or over the stored cap once re-encoded.
      TooLarge,
      /// Not a PNG by its signature: SVG, WebP, JPEG, GIF, anything else.
      Unsupported,
      /// A side of 0, or over `MAX_SIDE`.
      Dimensions,
      /// The decoder refused it.
      Damaged,
  }

  /// The upload `data` as a logo: decoded from base64, then re-encoded
  /// (`reencode`) under `MAX_STORED`.
  pub fn from_upload(data: &str) -> Result<Logo, Refusal> {
      // Checked from the length before anything is decoded (the review's O2).
      if data.len() > MAX_UPLOAD.div_ceil(3) * 4 {
          return Err(Refusal::TooLarge);
      }
      let bytes = base64::engine::general_purpose::STANDARD
          .decode(data)
          .map_err(|_| Refusal::NotBase64)?;
      if bytes.len() > MAX_UPLOAD {
          return Err(Refusal::TooLarge);
      }
      reencode(&bytes, MAX_STORED)
  }

  /// `input`, a PNG, decoded and written afresh: 8-bit, the colour type its
  /// pixels have once palettes and transparency are expanded, only `IHDR`,
  /// `IDAT` and `IEND`. An animated PNG keeps its first frame. Refused when
  /// it is not a PNG, a side is 0 or over `MAX_SIDE`, the decoder fails, or the
  /// result is over `max_stored` bytes (a parameter, so a test can reach it:
  /// the review's A4).
  pub fn reencode(input: &[u8], max_stored: usize) -> Result<Logo, Refusal> {
      if !input.starts_with(SIGNATURE) {
          return Err(Refusal::Unsupported);
      }
      let mut decoder = png::Decoder::new_with_limits(Cursor::new(input), png::Limits { bytes: DECODER_LIMIT });
      // The header alone first, so nothing is sized by it before it is
      // checked (the review's A2).
      let header = decoder.read_header_info().map_err(|_| Refusal::Damaged)?;
      if !(1..=MAX_SIDE).contains(&header.width) || !(1..=MAX_SIDE).contains(&header.height) {
          return Err(Refusal::Dimensions);
      }
      decoder.set_transformations(png::Transformations::normalize_to_color8());
      decoder.set_ignore_text_chunk(true);
      decoder.set_ignore_iccp_chunk(true);
      let mut reader = decoder.read_info().map_err(|_| Refusal::Damaged)?;
      let size = reader.output_buffer_size().ok_or(Refusal::Damaged)?;
      let mut pixels = vec![0; size];
      // The first frame, sized by what the decoder says it wrote (the
      // review's A3), never by the header.
      let frame = reader.next_frame(&mut pixels).map_err(|_| Refusal::Damaged)?;
      let mut bytes = Vec::new();
      let mut encoder = png::Encoder::new(&mut bytes, frame.width, frame.height);
      encoder.set_color(frame.color_type);
      encoder.set_depth(png::BitDepth::Eight);
      let mut writer = encoder.write_header().map_err(|_| Refusal::Damaged)?;
      writer.write_image_data(&pixels).map_err(|_| Refusal::Damaged)?;
      writer.finish().map_err(|_| Refusal::Damaged)?;
      if bytes.len() > max_stored {
          return Err(Refusal::TooLarge);
      }
      let etag = hex::encode(&Sha256::digest(&bytes)[..16]);
      Ok(Logo { bytes, etag })
  }
  ```

  ```rust
      encoder.set_depth(png::BitDepth::Eight);
  ```
