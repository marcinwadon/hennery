# The MCP gateway's connections in the web UI (plan 4e-i) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ] `) syntax for tracking.

**Goal:** the first half of 4e, the web UI's MCP screen (frontend spec §8; gateway spec §1, §9), over the connection routes plan 8a put on `main`, and only what an early tester needs to make the gateway usable:
- **The list** (`/mcp`): every connection, with the name agents see it by (`hennery-<slug>`), its server URL, its hat, how it authenticates, whether a token is stored, its state in plain words, and the vendor's note as escaped text cut at 300 characters.
- **Add, edit, delete:**
  - add a connection (step-up): a name, a slug, the server URL, the hat, no authentication or a token (with its header and prefix), every tool or a list, and the "internal network" switch with its warning;
  - edit one, sending only what changed, so a label or allowlist edit needs no step-up, and saying first when the change deletes the stored token;
  - delete one, confirmed, then stepped up.
- **The token,** write-only (step-up): typed into a password field that is read once and emptied at once, never held by the page, never shown again.
- **The hosts:** each connection against every host that is not revoked; a tick saves the whole set at once.
- **How a session gets it:** a persistent note that a connection reaches the sessions in its hat on the ticked hosts, as `hennery-<slug>`, from their next start or resume; and how Codex, Claude run with the operator's own CLI and any other agent command get it (without isolation, only when both are in the host's default hat; marked as subject to change).
- The screen exists only where the collector serves the connections (`features` names `mcp_connections`).

**Architecture:** all of it is in `web/`. No Rust changes, and no new dependency.
- `src/api/mcp.ts`: the six routes, typed.
- `src/lib/mcp.ts`: what the screen decides alone: the words for a state and a kind, the cut of a vendor's note, the form, what a change sends, whether it deletes the token, the next mount set.
- `src/components/`: `ConnectionForm.tsx` (create and edit), `TokenForm.tsx` (write-only), `Mounts.tsx` (the hosts).
- `src/screens/Mcp.tsx`, with its rules in `src/manage.css`.
- `e2e/mcp.spec.ts`: a connection created, its token set and mounted on a host paired with the command the Hosts screen shows.
- Shared files, touched minimally (4c edits some of them too): `components/Shell.tsx` (one import and one route), `api/errors.ts` (four messages), `api/client.test.ts` (their rows), `test-fixtures.ts` (a connection), `manage.css` (appended).

**Tech Stack:** as plans 4b and 4d-i: React 19.3.0, TypeScript 7.0.2, Vite 8.3.1, Tailwind 4.3.3, Vitest 5.0.3, Testing Library, `@playwright/test` 1.63.0 with the flake's Chromium. pnpm only.

## Decisions this plan makes where the specs are silent

A stronger-model security review on the maintainer's behalf (opus, 2026-10-03) answered "approve after amendments". It found no product question for the maintainer. The decisions it changed are marked "(amended: …)".

**What the review changed:**
- A1: the token field asked password managers to save it (`autocomplete="new-password"` reads as a password change): one that saved it could fill it into another connection's field, for another upstream and hat. It is now `autocomplete="off"` with the managers' opt-out attributes, in a `method="post"` form (decision 9).
- A2: an edit was compared with the connection as it is now, so an answer folded in while the form was open (a mount) could make a field the operator never touched look changed, and send it back stale. It is compared with the connection as the form opened (decision 6).
- A3: opening the add or edit form took the focused button away ("Add connection" disabled, "Edit" gone), dropping focus to the body. The form's name field takes focus; "Edit" is checked to have it after the token's-loss confirmation (decision 11).
- A4: the Codex note read as "every connection reaches Codex in the default hat"; it now says a session gets a connection only when both are in the host's default hat, names Claude run with the operator's own CLI as well (the host isolates only the pinned Claude), and says sessions in other hats get none (decision 12).
- Rulings: `not_connected` reads "Not used yet", not "Not checked yet": static and `none` connections are never probed, and live traffic through the proxy on `main` already sets `ok` and `needs_auth` (decision 3).
- Optional hardening taken: O1 ("Token saved." goes when a change deletes the token), O2 (the `204` is taken as the token stored; nothing is read back, so no older copy can undo a mount), O3 (the token field says where the token goes and for which hat), O4 (a `none` connection the server refuses says so, without a reconnect), O5 (the double-send guards are refs), O6 (tests and probes for the vendor's account, a refused token's-loss confirmation, a kind change on screen, and the URL, hat and host names as text), O7 (a new URL that does not parse asks nothing first: the server refuses the change whole).

**What the re-confirmation changed:**
- R1 (required): the on-screen note named Codex and Claude on the operator's own CLI, but not any other agent command (`--agent`), which the host does not isolate either (`Profile::Generic`). It now names all three (decision 12).
- R2 (required): the amendments had dropped the Cancel button's wait while a request runs, unrecorded: a cancelled form's request still landed, and could close or fill another card's form. Cancel waits again (`aria-disabled`, ignored while busy), with a test and a probe (decision 11).
- R3: the native-submit probe's reason was out of date (with `method="post"` the token would go in a request body, not the address); reworded (Task 3).
- R4 (recorded): the refs' "two presses in one frame" edge over state has no test of its own; the double-send tests pass either way.

1. **The route is `/mcp`, with nothing under it.**
   - **Choice:** the list, the forms and the dialogs all live at `/mcp`; a connection is edited inline in its card. There is no `/mcp/<id>`.
   - **Why:** the server serves the app at `/mcp` but answers `/mcp/` and everything under it itself (the gateway's proxy, `web.rs`'s `is_reserved`), so a reload there would never reach the app. 8f's OAuth return target is `/mcp` as well.
   - **Cost if wrong:** a detail view later takes a query string (`/mcp?c=<id>`), as 4b's hand-off says.
2. **The screen exists only with `mcp_connections`.**
   - **Choice:** `Shell` renders the MCP screen only when `features` names `mcp_connections`; otherwise the same placeholder as any view not in this deployment, and nothing is read. Unknown names are ignored. The rail keeps its MCP link (the mode decides the views; the feature decides the screen).
   - **Why:** 4b's hand-off: "the shell does not read `features` yet: 4e checks it before showing a gateway screen". Hiding the screen is not access control: the server answers every route behind the operator's session and step-up.
3. **A connection's state in words (gateway §7).** `not_connected` "Not used yet" (amended: the review's ruling; static and `none` connections are never probed, and the proxy sets their state from live traffic), `ok` "Working", `needs_auth` "Needs sign-in again", `error` "Is failing", and any state a newer collector adds "Unknown state". Nothing on an `error` connection suggests reconnecting or signing in: a click will not fix an outage (G-22). A `needs_auth` connection that authenticates with a token adds "The server refused the token: set a new one below.", since setting a token is the only way back for that kind; one without authentication adds "The server asks for credentials: edit the connection to send a token." (amended: O4).
4. **Vendor text is text, cut at 300 characters.** `status_note` and `account_label` come from the vendor: they render through `<Text>` (escaped, hidden characters made visible, bidi-isolated), cut at 300 code points with an ellipsis (`capped`). The label, the slug, the URL, the header and the prefix render through `<Text>` too.
5. **Adding a connection (gateway §1, §2).**
   - The hat starts at the default for new hosts, else the first hat; a hat being purged is not offered. The form says the hat is fixed once created. No hat is "selected in the UI" yet (gateway §1's default): the default for new hosts stands in.
   - The slug is shown as the server name agents will see, `hennery-<slug>`, as it is typed; the form says it cannot change later. The server checks it (`invalid`, `slug_taken`).
   - Authentication starts at "Token", the preferred kind where a vendor offers one (gateway §2), with `Authorization` and `Bearer `. The header and the prefix are sent only for a token connection. The token is set after the connection exists (decision 9): one form never holds both.
   - The server's refusal is shown in the form, which stays open with what was typed. `invalid` shows the server's own message (it names the field), as text.
6. **An edit sends only what changed.**
   - **Choice:** `changeOf(item, form)` names a field only when its value differs from the stored one: the label (trimmed), the URL, the kind, the header and prefix (only while the kind is `static`), the allowlist and the internal-network switch. An untouched form sends nothing and closes.
   - **Why:** the server asks for a step-up whenever the body *names* `url`, `cred_kind`, `internal_network`, `static_header` or `static_prefix`, even with the stored value. Sending the whole form would make every label edit a step-up.
   - **Against the connection as the form opened** (amended: A2): the form starts from that copy and a change is what the form changed of it, so an answer folded in while it is open (a mount's) cannot make an untouched field look changed. The token's loss and `has_credential` are judged on the connection as it is now.
   - **The token's loss is said first.** When a token is stored and the change names another kind, or a URL of another origin (scheme, host, port as the browser's `URL` parses them), a confirmation says the stored token will be deleted and must be set again, then saves; cancelling it sends nothing and keeps the form. A stored URL that does not parse counts as another origin; a new one that does not parse asks nothing, since the server refuses the change whole (amended: O7). Without a stored token nothing is asked.
7. **The allowlist has three states.** "Every tool" (ticked: `null`); unticked, the names typed one per line or separated by commas, trimmed, blanks and repeats dropped, the order kept; unticked and empty is `[]`, and the form says "No tool is allowed: agents see this server with none." before it is saved.
8. **The internal-network switch warns.** Ticked, the form says the gateway may then reach addresses on the operator's own network for this connection, and plain `http` to them, and to turn it on only for a server run there (kernel §7.1, maintainer decision 7).
9. **The token is written once and kept nowhere (gateway §9; the review's focus).**
   - **The field** is an uncontrolled `type="password"` input, never React state. Sending the form reads its value once and empties the field at once, before the request: whether the request succeeds, is refused, or its step-up is cancelled, the token is gone from the page and is typed again if needed.
   - **Password managers are asked to leave it alone** (amended: A1): `autocomplete="off"` (not `new-password`, which managers read as this site's password changing, and which Login and the step-up dialog's `current-password` share an origin with), `data-1p-ignore`, `data-lpignore`, `data-bwignore` and `data-form-type="other"`. Chromium's own offer to save a password field cannot be turned off from the page: recorded.
   - **No native submit:** the handler prevents the form's default action; the form is `method="post"` besides, so even a native submit would never put the token in the address bar.
   - **It says where it goes** (amended: O3): "Sent only to `<origin>`, for sessions in `<hat>`."
   - **Afterwards:** "Token saved. It is never shown again.", gone again once a change deletes the token (amended: O1). The `204` is the server saying the token is stored: that connection's `has_credential` becomes true and nothing is read back (amended: O2), so no older copy of the list can undo a mount saved meanwhile.
   - The token lives only in the client's request while it is in flight, including the one retry after a step-up.
10. **Mounts (gateway §1, §9).**
    - Every host that is not revoked is listed under each connection, ticked or not. A tick saves at once, with no confirmation (it is undone as easily) and no step-up (the server takes none: a mount reaches only a host the owner paired).
    - The set sent is the connection's own mounts with that one host changed, never the boxes on screen: a host this screen does not list (paired after it loaded) keeps its mount. The server's answer replaces the connection.
    - A tick while a set is being saved is ignored (a ref, so two ticks in one frame cannot both send; amended: O5). While the hosts cannot be read, the boxes are disabled and the error is shown.
11. **Nothing focused is disabled.** A button or box that has focus and is disabled drops focus to the page's body in Chromium, and the step-up dialog then returns it there. So while a request runs, the create and save buttons, "Save token" and the mount boxes say so (`aria-disabled`, `aria-busy`) and a second press is ignored (by a ref, amended: O5). Cancel waits for the answer too: a request already sent still lands, and must not close or fill another card's form (amended at the re-confirmation: R2). The add and edit forms open with focus on their name field (amended: A3). Focus goes to the new card's title after a create, to "Add connection" after a cancelled create, to "Edit" after an edit, a cancelled one or an accepted token's-loss confirmation, and to the page's heading after a delete.
12. **How a session gets a connection.**
    - **The note** on the screen, always shown: "A connection reaches the agent sessions in its hat on the hosts ticked below, as an MCP server named `hennery-<slug>`. Changes apply to new and resumed sessions." (gateway §1, frontend §8).
    - **Agents the host cannot isolate** (the lane's ruling, 2026-10-03: plan 8h, Codex's composed home, is deferred past the first test; amended: A4): "Codex, Claude run with your own CLI, and any other agent command (this may change): a session gets a connection only when both are in its host's default hat, and it also loads your own MCP servers (such as `~/.codex`), so it is not isolated. Sessions in other hats on that host get none." The host isolates only the pinned Claude (`claude_strict`); every other agent falls back (umbrella §8.5, plan 8e). The shorter "Codex sessions see these servers without isolation" would have been wrong for sessions in other hats, and "only sessions in the default hat get these servers" read as every connection reaching them. 4e-ii replaces this static note with what 8e reports per host and per session.
    - **When it is true:** the collector on `main` sends no servers until plan 8e. The lane ruled that 4e-i merges after 8e, so the note is never shown on a build where it is false.
13. **Messages.** Four codes gain plain words: `slug_taken` "This slug is taken: pick another." (worded to cover a local stdio server holding the slug too, as 8e will answer), `too_many_connections`, `unsupported_cred_kind`, `wrong_cred_kind`. `invalid` keeps the server's message, which names the field. `not_found` keeps the server's text.
14. **Deleting is confirmed, then stepped up.** The confirmation names the connection and `hennery-<slug>`, and says its token and mounts go with it and that sessions using it are refused from then on.
15. **The browser checks run a real host, hermetically,** as 4d-i's: the collector, `host join` and nothing else, each through `spawnHennery` in `scratchEnv`; the host only needs to be paired for a mount. The step-up is shown by answering the first `POST` and the first credential `PUT` with 403 `step_up_required` (`page.route`) and letting the retry through, since a session is stepped up for five minutes after setup; that the server refuses without a step-up is the Rust tests'. The upstream URL is never contacted (no probe before 8f).

  // What the MCP screen decides without the server (gateway spec §2, §7): the
  // words for a connection's state, the form a connection is edited in, and
  // what a change sends. The server checks every field again; these only keep
  // a request to what the operator changed.
  import type {
    CreateMcpConnectionRequest,
    McpConnectionItem,
    McpCredKind,
    UpdateMcpConnectionRequest,
  } from '../generated/protocol'

  /** A connection's state in words (gateway spec §7). `not_connected` is a
   *  connection no request has gone through yet (static and `none` ones are
   *  never probed; live traffic sets their state). `error` never asks for a
   *  reconnect: a click will not fix an outage. A state a newer collector
   *  adds reads as unknown. */
  export function statusLabel(status: string): string {
    switch (status) {
      case 'not_connected':
        return 'Not used yet'
      case 'ok':
        return 'Working'
      case 'needs_auth':
        return 'Needs sign-in again'
      case 'error':
        return 'Is failing'
      default:
        return 'Unknown state'
    }
  }

  /** How a connection authenticates, in words; a kind a newer collector adds
   *  is named as it is. */
  export function kindLabel(kind: string): string {
    switch (kind) {
      case 'none':
        return 'None'
      case 'static':
        return 'Token'
      case 'oauth_dcr':
      case 'oauth_client':
        return 'OAuth'
      default:
        return kind
    }
  }

  /** The longest vendor text shown (the status note): the rest is cut. */
  export const NOTE_LIMIT = 300

  /** `text` cut to `NOTE_LIMIT` characters (code points), with an ellipsis
   *  when it was longer. */
  export function capped(text: string): string {
    const chars = [...text]
    return chars.length <= NOTE_LIMIT ? text : chars.slice(0, NOTE_LIMIT).join('') + '…'
  }

  /** What the connection form holds. */
  export interface ConnectionForm {
    label: string
    url: string
    credKind: McpCredKind
    header: string
    prefix: string
    /** Every tool (`tool_allowlist: null`); else `tools`, which may be none. */
    everyTool: boolean
    /** Tool names, one per line or comma-separated. */
    tools: string
    internalNetwork: boolean
  }

  export const NEW_FORM: ConnectionForm = {
    label: '',
    url: '',
    credKind: 'static',
    header: 'Authorization',
    prefix: 'Bearer ',
    everyTool: true,
    tools: '',
    internalNetwork: false,
  }

  export function formOf(item: McpConnectionItem): ConnectionForm {
    return {
      label: item.label,
      url: item.url,
      credKind: item.cred_kind,
      header: item.static_header,
      prefix: item.static_prefix,
      everyTool: item.tool_allowlist === null,
      tools: (item.tool_allowlist ?? []).join('\n'),
      internalNetwork: item.internal_network,
    }
  }

  /** The tool names `text` lists: split on lines and commas, trimmed, blanks
   *  and repeats dropped, the order kept. */
  export function toolList(text: string): string[] {
    const seen = new Set<string>()
    for (const name of text.split(/[\n,]/)) {
      const trimmed = name.trim()
      if (trimmed !== '') seen.add(trimmed)
    }
    return [...seen]
  }

  function allowlistOf(form: ConnectionForm): string[] | null {
    return form.everyTool ? null : toolList(form.tools)
  }

  export function createRequest(form: ConnectionForm, slug: string, hatId: string): CreateMcpConnectionRequest {
    const request: CreateMcpConnectionRequest = {
      slug: slug.trim(),
      label: form.label.trim(),
      url: form.url.trim(),
      hat_id: hatId,
      cred_kind: form.credKind,
      tool_allowlist: allowlistOf(form),
      internal_network: form.internalNetwork,
    }
    if (form.credKind === 'static') {
      request.static_header = form.header.trim()
      request.static_prefix = form.prefix
    }
    return request
  }

  const sameList = (a: string[] | null, b: string[] | null) =>
    a === null || b === null ? a === b : a.length === b.length && a.every((x, i) => x === b[i])

  /** Only what `form` changed of `item`: naming a field the server steps up
   *  for, even unchanged, would ask for a step-up a label edit does not
   *  need. The header and prefix count only for a token connection. */
  export function changeOf(item: McpConnectionItem, form: ConnectionForm): UpdateMcpConnectionRequest {
    const change: UpdateMcpConnectionRequest = {}
    const label = form.label.trim()
    if (label !== item.label) change.label = label
    const url = form.url.trim()
    if (url !== item.url) change.url = url
    if (form.credKind !== item.cred_kind) change.cred_kind = form.credKind
    if (form.credKind === 'static') {
      const header = form.header.trim()
      if (header !== item.static_header) change.static_header = header
      if (form.prefix !== item.static_prefix) change.static_prefix = form.prefix
    }
    const allowlist = allowlistOf(form)
    if (!sameList(allowlist, item.tool_allowlist)) change.tool_allowlist = allowlist
    if (form.internalNetwork !== item.internal_network) change.internal_network = form.internalNetwork
    return change
  }

  /** `scheme://host[:port]` of `url`, or `null` when it does not parse. */
  export function originOf(url: string): string | null {
    try {
      const origin = new URL(url).origin
      return origin === 'null' ? null : origin
    } catch {
      return null
    }
  }

  /** Whether the server deletes the stored token for `change`: another kind,
   *  or a URL of another origin (gateway spec §4.6). A new URL that does not
   *  parse deletes nothing: the server refuses the change whole. A stored one
   *  that does not parse cannot be compared, and counts as another origin. */
  export function dropsToken(item: McpConnectionItem, change: UpdateMcpConnectionRequest): boolean {
    if (change.cred_kind !== undefined && change.cred_kind !== item.cred_kind) return true
    if (change.url === undefined) return false
    const before = originOf(item.url)
    if (before === null) return true
    const after = originOf(change.url)
    return after !== null && after !== before
  }

  /** The mounts with one host ticked or not, sorted: the set a save sends
   *  is the connection's own, so a host this screen does not list keeps its
   *  mount. */
  export function mountsWith(mounts: string[], hostId: string, on: boolean): string[] {
    const set = new Set(mounts)
    if (on) set.add(hostId)
    else set.delete(hostId)
    return [...set].sort()
  }

  /** The name agents see the connection as. */
  export const serverName = (slug: string) => `hennery-${slug}`

  /** Whether a narrow-screen rule makes a tick box's label 44 px tall. */
  function tallLabel(label: Element): boolean {
    for (const sheet of document.styleSheets) {
      for (const rule of sheet.cssRules) {
        if (!(rule instanceof CSSMediaRule) || !/max-width:\s*767px/.test(rule.media.mediaText)) continue
        for (const inner of rule.cssRules) {
          if (inner instanceof CSSStyleRule && label.matches(inner.selectorText) && parseFloat(inner.style.minHeight) >= 44)
            return true
        }
      }
    }
    return false
  }
