# Managed adapter audit for PR #378

This candidate updates Claude ACP 0.112.0 to 0.113.0 and Codex ACP 2.12.0 to
2.12.1. Claude Agent SDK 0.3.332, Codex CLI 0.172.0, Node 24.22.3 and every
other resolved adapter dependency remain unchanged. It also prepares 0.7.1.

The maintainer explicitly selected CI and source audit without live-agent
acceptance for this update on 2026-11-27. This document does not claim provider,
MCP-isolation or delegation acceptance with the new adapter set. The earlier
four-case macOS Codex subset belongs to PR #375 and its recorded source.

## Published package comparison

Both old and new npm tarballs were fetched anonymously from the pinned public
registry URLs and verified against their committed lockfile SHA-512 integrity.
The package version documents agree with the lockfile URLs and integrity.

Codex ACP's published `dist/index.js` changes exactly two bytes: its embedded
package version and the embedded `@openai/codex` range, from `^0.171.0` to
`^0.172.0`. The other changed file is `package.json`, with those same changes.
There is no other executable bundle change. Hennery already pins CLI 0.172.0,
so the [existing native deletion source audit](2026-11-26-runtime-375.md)
continues to describe the same CLI bytes and contract.

Reviewed Codex adapter source from
[`2a627def`](https://github.com/agentclientprotocol/codex-acp/tree/2a627def45e1d228cdb7fd9a7cd454ac81281e6f)

## Claude adapter review

Reviewed the four upstream commits between
[`aa93ed06`](https://github.com/agentclientprotocol/claude-agent-acp/tree/aa93ed06c1b0d54642727b9ab23b94f953c49cca)
and [`764fb84f`](https://github.com/agentclientprotocol/claude-agent-acp/tree/764fb84f9f668dc1b490aa726ee982c1e53ccd7e):

- `/plugin` is handled by the adapter. Its CLI runner uses `execFile` with
  argument arrays, an abort signal, an output bound and a timeout. Commands
  refuse foreground work; prompt admission, steering, cancellation and teardown
  share the adapter-command slot. Remote `sdk-url` sessions do not run local
  plugin commands against the adapter machine.
- Remote Control startup follows the CLI's `remote_control_auto_enable` result.
  Upstream can derive this from settings, policy or a vendor rollout; it is not
  necessarily a new explicit user opt-in. A missing field means off, an explicit
  `/remote-control off` survives query replacement, and prompts wait for the
  startup notice. No Hennery or machine configuration is changed by this PR.
- MCP settings delivery retains the same argv/initialize choice; the extracted
  remote-session predicate preserves the `settings`/`sdk-url` cases. Hennery's
  strict managed-MCP profile and hook settings are unchanged.
- The background-task result/level ordering fix changes ACP v2 task tracking.
  Hennery's separate optional ACP v2 proposal remains outside this update.

Current-head CI records package integrity/signatures, manifest regeneration,
safe extraction, dependency audits and ordinary application/packaging results.
Those checks do not substitute for the live acceptance explicitly waived above.
