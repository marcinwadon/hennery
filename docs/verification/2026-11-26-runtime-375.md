The candidate updates Claude ACP to 0.112.0 / Agent SDK 0.3.332 and Codex ACP
to 2.12.0 / CLI 0.172.0. Node remains 24.22.3. Qualification uses the existing
`packaging/runtime_acceptance.py` driver in isolated, source-bound checkouts.

## Codex deletion contract

Reviewed upstream `rust-v0.172.0` at immutable commit
[`3d86e43b075adeba2193ec5c22ac92f55afd82e6`](https://github.com/openai/codex/tree/3d86e43b075adeba2193ec5c22ac92f55afd82e6).

- [`ThreadDeleteParams` and `ThreadDeleteResponse`](https://github.com/openai/codex/blob/3d86e43b075adeba2193ec5c22ac92f55afd82e6/codex-rs/app-server-protocol/src/protocol/v2/thread.rs)
  retain camel-case `threadId` and an empty successful result.
- [`thread_delete_response`](https://github.com/openai/codex/blob/3d86e43b075adeba2193ec5c22ac92f55afd82e6/codex-rs/app-server/src/request_processors/thread_delete.rs)
  enumerates the native spawned subtree, checks attachment ownership and
  prepares each thread before delegating to the local store. It still reports
  an unpersisted thread through the existing ephemeral refusal prefix.
- [`delete_threads`](https://github.com/openai/codex/blob/3d86e43b075adeba2193ec5c22ac92f55afd82e6/codex-rs/thread-store/src/local/delete_thread.rs)
  holds lifecycle/writer locks, refuses external fork references, removes
  materialized history and both plain/compressed rollout files, removes name
  index entries, then strictly deletes state rows. Cleanup errors propagate;
  the complete state retry graph remains until rollout removal finishes.
- [`thread_history::delete_thread`](https://github.com/openai/codex/blob/3d86e43b075adeba2193ec5c22ac92f55afd82e6/codex-rs/thread-store/src/local/thread_history.rs)
  transactionally removes `thread_items`, `thread_realtime_items`,
  `thread_turns` and `thread_history_projection_state`. The existing live
  deletion test already checks all four tables as well as state, rollouts and
  the session index.
- The fork-reference substring remains unchanged. Missing threads still map
  to the existing missing-thread prefix through `thread_store_delete_error`
  and `core_thread_write_error`; the historical missing-rollout prefix remains
  a conservative compatibility case. The core thread manager retains the
  internal-worker refusal prefix, and `core_thread_write_error` maps that
  invalid-request detail without wrapping it. Unknown errors remain failures
  rather than triggering archive fallback after deletion was sent.
- [`initialize`](https://github.com/openai/codex/blob/3d86e43b075adeba2193ec5c22ac92f55afd82e6/codex-rs/app-server/src/request_processors/initialize_processor.rs)
  still returns `codexHome` from the configured absolute home.
  [`find_codex_home`](https://github.com/openai/codex/blob/3d86e43b075adeba2193ec5c22ac92f55afd82e6/codex-rs/core/src/config/mod.rs)
  requires an explicit home to exist and canonicalizes it. The live host path
  verifies that this is exactly the supplied scratch home before deletion.
- The CLI package remains `codex-cli` and uses clap's package version output.
  The native version line and the actual initialize/delete exchange are also
  exercised by the pinned deletion test; source inspection alone does not
  establish their live outcome.

No refusal classification, deletion safeguard, timeout or acceptance assertion
is relaxed for this update.
