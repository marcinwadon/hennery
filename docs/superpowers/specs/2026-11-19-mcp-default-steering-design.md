# External MCP prompt delivery

An external client can add context to an attached ACP turn through the existing session_prompt tool. The optional delivery argument accepts auto (the default) and queue. A parked session resumes through the existing verified attachment path. An explicit queue request waits for a new turn. A compatible running or permission-blocked turn can accept auto input. Only the operator can answer a permission.

## Dispatch and authority

Retain the external_operations ledger, key digest, bounded admission, sealed upload bindings and worker. Authenticate the bearer credential on each public call. Accepted work survives access-token refresh. Check the current live grant, revision, session scope, host realpath, resolved hat and attached MCP source policy when dispatching. Bind the host, canonical cwd, granted root and hat observed by preflight through the actual send. Legacy untracked attachments require selected legacy policy. Tracked attachments require matching requested/applied evidence and current policy/revision. The store mutex orders the final authorization, attempt transaction and mailbox handoff against policy mutations. Sharing the steering transport and immutable history format lets both input sources benefit from correlated ACP outcomes while the external worker retains its own authority and queue.

Choose the oldest undelivered external prompt across clients for the session. Snapshot the busy target at admission so a later turn cannot acquire an older hint. Operator and delegated queue entries retain normal new-turn priority. Steering can add input to the current turn while those entries wait. The existing queue hold and close fences still apply. An earlier prompt that started its ordinary turn or has a confirmed steering admission allows a subsequent hint to steer. Earlier queued, unconfirmed and ambiguous inputs fence later prompts. A parked/idle admission or a confirmed steering miss commits to ordinary FIFO delivery even if another turn starts. Legacy queued operations retain ordinary scheduling.

## Receipts and persistence

A new queued auto operation has no promised turn. Assign an ordinary turn ID only when opening that turn. Store ordinary ownership in external_operations.turn_id. For an attempted steer keep that column empty and record the actual target in result.turn_id, with result.delivery = steering and result.admission = pending. The public receipt projects the actual target at its top level as well. A durable request ID, deadline and steering_attempt event precede the send. The attempt includes original stored content, actual turn and external-client origin. Its attachment references survive queue changes. Confirmed injected input produces one user_steering event with that same origin and turn. Late confirmation appends at the raw cursor and anchors at the attempt in the folded view.

An injected operation is running with result.admission = confirmed until the target ends. A confirmed injection into an ended turn completes immediately with that turn's outcome. A turn end alone cannot settle pending admission. While steering admission is pending, a timeout, disconnect, collector restart or ambiguous error reports delivery_unknown and suppresses redelivery. Confirmed admission survives restart. If a definitive fact never arrives, later external prompts remain queued for that session. Correlated late facts can still settle it. A definitive rejection fails. PromptRequired, typed unavailability and a proven unsent mailbox handoff restore ordinary delivery once, subject to the original authority and session state. Queued cancellation or editing wins until dispatch claims the payload. A handoff precludes withdrawing the input. Receipts for ordinary dispatched turns include result.delivery = turn and the real turn ID. The initial queued result is empty.

The client receives the same public operation through admission, operation_get and session_wait. The queue filters completed steering operations before applying its cursor limit. For a steering operation, waiting_on_operator reflects its actual turn. Replaying a request key cannot enqueue another input, including after fallback, revocation or a later turn. The agent adapter and host protocol need no extension.
